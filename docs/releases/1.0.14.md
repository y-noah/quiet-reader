# New 1.0.14：启动与预取卡顿修复

2026-11-07，versionCode 63。用户反馈 1.0.13 刚进入应用时严重卡顿。此前验收重点是点击后正文出现的时间，未充分验证缓存恢复与持续预取期间的交互流畅性，原结论范围过大。

## 修复

- 缓存发布、恢复、话题预取和曝光采样尊重原生首屏绘制与 WebView 异步初始化顺序，避免提前读取 CookieManager 而在 UI 线程同步启动阅读引擎。
- 命中内存缓存的预取队列每次最多处理两项，后续交还消息循环；不在一个主线程任务中遍历整批正文。
- 同一次同步校验内复用同 URL 的登录指纹。操作结束即清除，包括异常退出；不跨操作缓存账号状态。
- 未完成的子正文不再触发整表刷新，实际展示列表未变时不刷新。滑动期间暂缓话题列表发布。
- 话题图像只由一个准备队列负责，去掉重复图像预取。
- 滑动时停止派发后续预取，在途请求允许结束，但其回调不再重新加入子帖队列；空闲后继续预取。

首批 3 篇及图片提前准备、后续自然追加、局部收起均保留。

## 真机验证

同一 PHY110，正式包、不清数据，force-stop 后启动，立即交替向上/向下滑动 16 次，每次手势 280 ms。使用 Android gfxinfo 实际渲染统计，不将后台缓存命中率当作前台性能。下表为最终安装包；中间版本结果不混入最终结果。

| 场景 | 帧数 | 超过帧期限 | 95 分位 | 99 分位 |
| --- | ---: | ---: | ---: | ---: |
| 1.0.13 冷启动立即滑动 | 291 | 26（8.93%） | 150 ms | 300 ms |
| 1.0.14 最终包冷启动立即滑动 | 573 | 6（1.05%） | 9 ms | 13 ms |
| 1.0.14 最终包启动后预取 25 秒，再滑动 | 1008 | 48（4.76%） | 15 ms | 38 ms |

最后一组包含启动、预取和滑动全段，不能与纯滑动直接等同比较。最终两组最大帧耗时直方图区间分别为 150 ms 和 113 ms，仍有长帧，不宣称零卡顿。网络来源和设备负载也会变化，这些为本设备采样，不是所有设备保证。

正式包点击当前未读贴吧热议“Faker放话BLG将遗憾止步四强”：351–385 ms 截图帧正文可见但图片仍占位；595–627 ms 帧图片可见；737–781 ms 帧转场落定。图片占位不计为加载完成。

1020 项单元测试全部通过；真机深、浅主题各 160 项检查通过，新增“滑动期间在途请求结束不得重新派发子帖”回归。lint 0 errors、40 warnings。沿用原发布签名并覆盖升级。

中间包在持续预取后仍出现约 400 ms 长帧，因此继续合并失败回调及保留检查中的同步校验，并修复滑动后重新入队；该结果保留为排查记录，不计为最终包结果。
