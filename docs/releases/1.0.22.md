# New 1.0.22

修复知乎正文中同一张图片上下显示两遍的问题。上一个版本处理的是续载时保留图片节点，未覆盖本次实际存在的重复提取。

## 原因与实现

真机问题 `https://www.zhihu.com/question/2104954238514230174` 的一个图片容器同时含有 `noscript` 备用缩略图和 `RichText-ConditionalImagePortal` 中的实际图片。它们可能使用720w、1440w、原图及pic1、picx、pica等不同知乎CDN地址，原解析器逐个输出后把8张图变为15个图片块。

- 新提取仅在同一figure内、有对应实际图片时移除noscript备用图片；只有备用图时保留它，不跨图片容器或回答做全局去重。
- 旧缓存及阅读历史解码时，只修复同一段落序列中相邻、地址不同、已知知乎图片内容标识相同的尺寸/CDN副本。不同回答、文字隔开的图片及相同地址的主动重复保留，不清空登录或全部缓存。
- 不修改上一版的DOM协调、推荐、来源、刷新或缓存预算。

## 验证

- 真机取得公开正文区域作为固定回归样本，不导出Cookie、账号存储或页面账号区域。
- 1053项单测通过，包含6项新图片用例：真实样本、旧缓存恢复、备用图单独存在、有意重复、跨回答、不同CDN和伪装域名边界。
- 第一轮真机修复复测仍发现pica域名未覆盖，已补充测试修正；最终同一文章连续三轮实际获取均为8张，不再成对输出。失败轮次保留本地诊断，不计为通过。
- 临时诊断组件在验证结束后卸载，恢复正式签名包和原USB亮屏设置。
- 正式签名1.0.22（71）原位升级后，重新从热搜池搜索打开同一问题；实际截图确认“韩国女孩”图片只显示一次，下一张为原文股票图。手机仅保留主应用，USB亮屏恢复为0。
