# 1.0.1：固定十五条与后续轮次预备

范围：统一阅读页导航、首页密度、刷新预缓存。相似去重算法保持暂停，不扩充来源。

## 首页与阅读页

- 每轮最多十五条，供应足够时固定十五条，不无限加载。所有首页标题统一15sp，简介最多一行并在超出时省略，正文阅读字号沿用用户设置。
- 阅读页移除顶部返回按钮，系统侧边返回保持原逻辑。向下浏览隐藏工具栏，反向浏览显示；停止不自动显示。
- 工具栏浮层只平移，不改变正文视口尺寸。首屏正文预留工具栏空间，正文滚动后能使用顶部区域。

## 预备与缓存

- 当前轮与未来准备区分开：已有首页换轮仅在整轮正文持久化并逐篇回读验证后发布；冷启动/恢复必须先绘制可用原生标题列表，随后释放可选阅读器预热并继续缓存。首屏不能受整轮缓存或资源预算阻塞。普通换轮等待期间保留当前屏，未准备正文不能先发布再让点击触发网络补取。准备未来内容不计曝光、不产生兴趣反馈。
- 本次前台会话已经展示的整轮成员不再放进预备队列；分组中的任一成员已展示，也跳过该组。会话记录有界，不替代持久阅读记录。
- 刷新消费队列第一轮，发布后从池中补足未来四轮。未来条目身份在存储层重新核验，偏好版本变化时重排；正文语言证据更新仅改变来源版本时，对最新合格列表逐条复核正文身份，不能因此整批丢弃已准备内容。标题、正文入口或分组成员改变的条目重新准备。
- 候选不足不伪造六十条。队列耗尽时沿用已有刷新排序与阅读历史策略，允许有限旧内容回流，不能承诺热榜不变时永远有新内容。
- 正文仅一个预加载器顺序获取；内存缓存仍为32MiB，正文磁盘预算仍为96MiB，单正文上限2MiB。扩大的是有界任务窗口，不是同时保留七十五个网页。
- 当前与未来轮次共同参与保留清单，换轮不清掉将要阅读的缓存。滚出窗口的旧缓存可以回收。登录Cookie、缓存命名空间、内容元数据仍须匹配，登录壳和失败页不可当成功正文。
- 正文优先；首页当前轮每篇最多提前四张图，未来轮每篇最多一张图。图片仍受原有单图、单次字节数、执行时间限制，视频不预下载。

## 五分钟更新与生命周期

- 首页处于前台时，五分钟触发一次候选来源更新。连续多次手动刷新主要消费本地队列，不重复抓整套榜单。
- 自动更新只替换准备区，已显示列表及滚动位置不受影响。失败保留已有内容。同一来源更新周期内，中间语言证据或排序回调保持有效预备条目的顺序，避免反复清掉刚完成的缓存；新一轮来源收集也保留仍有效的已备条目，由最新候选身份校验淘汰真正失效项，不能在更新开始时先清空可用队列。
- 启动或显式换轮可授予一次最多四分半钟的有限缓存窗口（为本地模型整理留出时间，避免慢来源占满整个更新周期）；授权的五分钟来源更新周期可开启新窗口。单个正文/图片回调不续期。
- 后台、页面退出、关屏、省电、低电量、发热、内存压力受既有策略约束。后台移除周期回调且取消预加载，不注册后台服务、定时唤醒或持有唤醒锁。阅读页只延续有限邻近预读，返回首页再检查更新。
- 五分钟表示发起检查的频率，不是对网络延迟、来源榜单更新速度或所有正文完整可读的保证。

## 验收

- 单元测试覆盖固定十五条、四轮不重复、旧身份失效、来源筛选、候选不足、有限预算。
- 隔离模拟器用真实Controller与缓存、受控来源/正文传输验证七十五篇顺序预取，连续四轮显示预备内容且正文缓存命中；来源失败不改当前屏；后台无新请求或周期回调。
- 阅读页深浅色验证：无返回按钮，下滑隐藏/上滑显示/静止保持，WebView高度不变，现有菜单可达。
- 真机手感、真实网络命中率、长期耗电需另行实测；不得将受控模拟器结果描述成真机或全平台成功率。

## 2026-10-31 完整缓存目标补充（覆盖前述宽松验收）

- 排名优先，尚未下载的高排名条目不能被已缓存的低排名条目任意替代。只有确认正文获取失败的具体内容版本，才可暂时跳过，五分钟后重新具备尝试资格；不形成平台偏好或永久屏蔽。
- 就绪证明绑定内容版本、账号指纹、缓存命名空间及原始获取时间。写盘入队、RAM 命中、加载壳、登录或失败页均不等价于持久化成功。
- 发布前再次逐篇读取实际磁盘记录，验证版本及当前会话。全轮准备后才能停止刷新动画并发布下一屏。连续点击合并；取消、页面离开、后台回调不能偷偷替换当前屏。
- 当前已发布正文受存续保护；十分钟在线新鲜度过期不会让当前屏突然点击丢失正文。保留原始获取时间，不把阅读或固定动作当作新获取。账号及内容身份仍然验证，最长历史有效期保持不变。
- 换批清理不再改变账号获取 epoch；仍保留真正账号/命名空间失效拦截。相同 URL 的旧元数据写入不得覆盖保留的新元数据。
- 有限前台预算耗尽时保留已显示屏并结束本次刷新；不得显示未缓存内容、无界重试或伪造完整命中。此类保留属于准备不足，不能计为瞬时刷新成功。
- 真机验收分别记录「点击刷新前已经完成缓存」和「发布时完成缓存」；两者不能混称。首屏可见与正文就绪分别计量；首屏允许先可读，不能据此声称 15/15 提前缓存。后续预备四轮目标每屏 15/15，正文实际打开验证另记。受控来源通过不能代替真实来源通过。

## 预备顺序与交互连续性

- 换轮提交须保存完整有效预备队列的顺序，不能只提升首十五条再将其余预备条目放回旧排序。首屏某条获取失败后，补位优先来自后续已规划屏，且仍经过正文身份、来源资格与会话验证。
- 窗口变更时保留仍在新窗口内的在途获取；仅真正移出的请求取消。滑动期间不启动新的正文、图片或模型任务，但允许已有的单一正文请求完成，避免每次手势重复加载同一慢页面。退后台、息屏、策略限制及关闭仍取消。
- 预加载可以先尝试已有专用解析器支持的共享 Cookie 原生响应，无法取得有效正文或返回权限壳时继续网页后备。不得把原生请求成功等同于正文就绪；最终仍要持久化回读验证。

- 前台预算上限调整为四分半钟，仍只处理当前十五篇与未来六十篇的有界窗口；完成后立即空闲，不会为了用满时间增加下载。此前三分钟包含冷首屏准备，慢来源会在剩余预备内容未完成时被提前截断。保持后台/息屏取消和策略限制，不增加并发，也不扩大缓存字节预算。
- 实测微博、百度、贴吧原生试探均退回网页（样本7/14/9篇），收回这些没有实测收益的额外 HTTP 试探；保留已经验证有效的 BBC / V2EX / 虎扑共享 Cookie 原生路由及必要网页后备。

## 空白首页回归验收

- 必须在开启自动预加载、阅读器仍处于 deferred 状态下启动；原生首屏先可见，其首帧必须释放阅读器准备。禁止以 test_skip_fetch 绕过这条路径。
- 首篇正文未完成时，后台/预算耗尽/恢复不能清空已展示标题。
- 真机移除测试驱动后，普通启动、返回退出重开、强停重开、息屏恢复、后台返回分别核对；插桩保活通过不能替代。
