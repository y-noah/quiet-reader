# 列表冻结、技术来源、缓存与图片（1.0.21）

## 用户边界

- 用户明确确认：不主动刷新，正在显示的首页列表保持不变。后台允许更新候选池和预缓存，不能因正文准备完成、模型排序完成或定时采集而替换当前列表。
- 科技来源要技术进展、科研、编程/开源等文字内容，不新增手机电脑新品发布、导购类平台。本轮只新增奇客Solidot与InfoQ中文；不新增少数派、爱范儿。既有来源开关不被覆盖。
- 缓存做多轮实际打开统计：每轮刷新后首页停留60秒，记录总打开数、1秒内正文可见、未秒开、失败、缓存来源与耗时。重复/压力测试主要使用隔离模拟器；手机只作关键验证。
- 图片不要因回答自动续载而先显示再重新加载一遍。

## 实现

1. 首页首次采用一个可用批次后，不建立可在正文预热结束时重新发布的admission；背景采集/排序继续只进入pending和reserve。阅读返回时保持当前条目和顺序，只更新已读样式；主动刷新继续排除已读原文。显式刷新和显式设置操作仍正常生效。普通冷启动仍遵循既有批次恢复逻辑，本次不改为跨进程永久固定首页。
2. Solidot只解析网页明确的“热门文章”侧栏，排除置顶课程推广、热门评论与主站其他导航。InfoQ使用官方中文RSS，排除/video/，追踪参数规范化为原始文章URL；准确标识为最新技术文章，不伪造热度或加平台偏好权重。两来源均使用明确正文容器及现有统一阅读排版。
3. FeedStore迁移12→13为新来源插入默认开启项，不修改任何旧来源开关。公共文章不依赖新增key或服务端。
4. 回答续载及话题预取结果改为自有正文DOM协调更新：保留同一section/图片节点，不重载整个WebView；仅新增或变更文本、回答和续载状态。保留1.0.20按每篇帖子选择图片referer的逻辑。失败才走安全重绘。
5. 当前页的普通正文先于需动态浏览器的正文预取，当前页所有条目始终先于未来批次；只改请求顺序，不改展示排序、平台配额、身份、并发数或有限缓存预算。不能为了缓存优先而删掉用户想看的慢来源。
6. 重复布局回调报告相同首页位置时，保留已经安排的预取任务，不重新延后650毫秒，不暂停已在进行的图片预热；实际位置变化及交互暂停仍保留原有节流。有限缓存预算不因被动布局回调续期。

## 验收

- 初始预热、静止、返回、后台候选准备不改变当前批次；刷新仍显示新批次且动画结束。
- 新来源真实列表及正文样本可解析，拒绝伪装域名、非文章路径；InfoQ视频不进入池。
- 真实WebView连续24次续载，原图节点、naturalWidth和图片资源请求数保持，页面身份不变；深浅色及大字号均回归。
- 缓存报告不得把文件存在当作命中、DOM就绪当作视觉可读；必须记录点击至视觉提交。保留失败轮次与诊断结果，不能只报成功轮次。
- 图片正文用已解码且位于可视区域的正文图片验证，不再只等待20字正文；短文本及分区正文同样可作为实际DOM依据。纯图未解码或只显示标题都不能算成功。
