# 刷新与重开稳定性修正

用户优先级：稳定、好用；刷新必须有可感知的换批结果，不得被少数慢正文阻塞。此文覆盖旧文中“整轮正文全部就绪才允许任何手动换屏”的约束。

## 行为

- 首页仍为15条、无无限加载。正文、登录、偏好及相似去重功能不扩展。
- 当前屏及后续四轮仍提前缓存。准备区已有内容时，刷新只做本地身份校验、选取下一批与存储提交；正文缺口继续缓存，不能锁住整个刷新流程。冷启动原生列表先可见。
- 池已耗尽时，在现有合格内容中按最早发出顺序回流；池未更新不伪造新闻。只有不足30条时允许相邻两屏存在不可避免的交集。
- 为整批已发出的内容保存独立记录，7天、最多2500个候选。记录不等于阅读或曝光，不改变兴趣与平台反馈。分组任一成员已发出，该组计为已发出。
- 新建普通首页（无系统恢复状态）优先未发出的合格内容；当前窗口从正文/设置返回保持原批次。系统恢复状态、旋转与短暂前后台切换保留位置。
- 同一批次内仍保留已有相关性次序与预备队列次序。准备队列失效时按当前来源与偏好重新校验；禁用来源及旧偏好结果不得提交。
- 三次快速点击合并成一次；动画在实际替换列表首帧前停止。正文下载、榜单收集和推荐模型的后续完成不得延长本次刷新环或偷偷换第二屏。
- 首次升级新增delivery历史表，不删除来源配置、候选、反馈、阅读历史或登录Cookie。旧首页本批在重开选取下一批之前补入已发出记录。

## 验收

- 模拟器：正文永不回调时连续五轮刷新，每轮15条、无此前整批重复、无需正文完成；普通重开换批，现有页面恢复保留批次。
- 数据：v9原位迁移至v10；发出记录不产生兴趣或实际曝光；历史到期与容量清理；禁用来源后拒绝旧结果。
- 控制器：缓存四轮、失败补位、息屏/后台、取消、错误归属、动画同帧、来源后台收集与用户刷新相互独立。
- 真机：普通签名包原位安装；8轮点击/下拉混合刷新、快速重复点击、3次重开及移除驱动后的普通启动/息屏/后台恢复；记录真实耗时，失败不得隐藏。缓存就绪率单独记录，不以界面可见冒充提前命中。
