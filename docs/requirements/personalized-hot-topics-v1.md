## 1. 产品目标与不可变约束

### 1.1 要解决的实际问题

用户当前在五个平台热榜里实际愿意阅读的内容不足五分之一，有时不足十分之一。这是用户的体验描述，不是已采集的统计值。

V1 的目标是：扩大平台热门内容候选池，理解用户的选择，从中找出更可能想看的话题，提供稳定、有顺序、可继续调教的中文阅读列表。不是给旧热榜换皮，也不是让用户不断输入搜索词，更不是单纯增加 RSS 后按时间排列。

目标优先级：

1. 前排内容逐渐更符合用户兴趣，明确不喜欢和已看够的内容不反复出现；接受冷启动和逐步调教。
2. 默认推荐全程本地，日常浏览不需要 Key，不产生模型 API token 费用。
3. 容易实现、维护和定位误判；不训练大型推荐模型，不建设推荐服务器或向量数据库服务。
4. 控制整个 App 的内存、CPU 活动、网络活动和耗电，阅读操作优先于推荐计算。

“都是我想看的”是优化方向，不能把它写成已经保证 100% 命中。必须用用户真实反馈和未参与调参的样本验证效果。

文字流来源优先于视频主导来源扩张。当前开发顺序为：文字平台热门候选的真实性与供给质量、内容/平台偏好及排序效果、文字正文和讨论阅读/预取，再到非重点来源适配。来源选择是候选供给契约，不是给某平台预设热度加分。“有价值”通过用户愿意阅读/保存/多看与明确少看等反馈逐步校准，不能由开发者把科技、财经等题材硬编码为更有价值；现有平台榜单名次和跨站转载数也不能证明个人价值。

### 1.3 V1 不做什么

- 不恢复已删除的“全网客观总热度榜”，不跨平台相加浏览量/点赞量/热度值。
- 不以全网主动搜索、RSS 长文发现、英文翻译、AI 摘要、聊天窗口为主功能。
- 不训练/微调手机上的模型权重，不上传兴趣画像和阅读历史，不需要账号或服务器。
- 不使用 Jev API，不内置 DeepSeek/GitHub 等 Key，不把历史提供过的 Key 用作新增方案的依赖。
- 不承诺获得各平台全部内容；登录限制、付费墙、访问失败必须明确呈现。
- 不为了保持“零 token”而用粗糙关键词结果冒充完成双模型推荐；运行时降级必须可诊断。
- 不将原型中的虚构文章、阅读分钟数、硬编码偏好和固定示例排序作为真实内容发布。

| `DiscoveryCore.java`（未接入草稿） | 可审阅复用纯解析/工具思路 | 其 RSS 默认源、英文条目、固定规则分数不是 V1 设计；在 M00 决定重构或移除，不能顺势接入成为最终实现 |

现有 `README.md`、`DEVELOPMENT.md` 中的历史产品约束、旧版本验收数量不能覆盖本文，也不能作为新版本完成证据。已有登录状态、收藏数据、阅读位置不可因迁移而清空。

### 3.1 可移植原型引用

- 保留浅/深背景、轻边框圆角卡片、标题/短摘要/来源层级。用户后续明确移除应用内品牌/Logo、顺序号、分类、稍后读及大段首页说明；设置/状态使用紧凑顶部入口，来源与推荐诊断进入设置。旧原型中的这些元素不再作为验收要求。

### 3.2 信息架构

1. **单一推荐首页**：文字热门卡片，不显示应用内Logo/名称、分类栏、排名数字或大段推荐说明。有限一批约首屏加一次自然上滑看完，按视口选完整前缀、20仅安全上限，底部不追加。
2. **紧凑页头入口**：设置图标与状态圆点。圆点无论有没有新内容都回顶部，并与顶部下拉一样显式换批；没有独立重复刷新按钮。向下浏览隐藏页头，停止后继续隐藏，向上浏览才显示。
3. **设置**：同类项相邻、精简分组；来源控制是其中一项，资源/模型诊断和偏好反馈历史在二级页。无独立稍后读入口，旧保存数据仅保留迁移兼容。

来源管理统一由设置进入，保留平台开关、单平台榜单、登录/原网页入口、最近成功获取时间与明确失败状态。系统返回和页头返回均回到进入前页面及位置。历史“发现/稍后读”底栏已被用户删除稍后读的要求覆盖。

不另设“热搜 / 个性化推荐 / 主动搜索”三个主要入口。旧总榜说明文字不恢复。来源故障详情在设置的内容来源页，不长期占据首页大段文字。

### 3.3 卡片契约

- 标题必须来自实际候选；摘要只取来源已提供的文本，缺失时不强造摘要、不重复标题凑版面。
- 不显示左侧序号或排名数字。
- 显示主来源；同事件可打开“另有 N 个来源”选择器；主来源默认选可读且信息充分的已验证入口，可记住用户选择。
- 分开显示发布时间与上榜/获取时间。源未提供发布时间时不得把抓取时间伪装成发布时间。
- 无正文长度证据不显示“预计阅读 X 分钟”。
- 推荐依据只能来自可追溯的本地特征，留在设置/详情，不占首页卡片。相似度/重排分数不是“喜欢概率”，不展示伪精确百分比。正文页不显示来源/分类等解释性段落。
- 反馈菜单保留多看这类、少看这类、这个事件看够了等调教行为，不提供稍后读；事件看够不等于屏蔽整个主题。
- 进入卡片打开主来源现有阅读流程；返回恢复同一列表快照、事件锚点和像素偏移。

### 3.4 页面状态与稳定性

| 状态/操作 | 行为 |
|---|---|
| 首次启动、无偏好 | 可跳过的真实话题选择，不预设用户喜欢科技/实用经验；直接使用冷启动列表 |
| 有缓存 | 先显示上次列表与时间，再获取增量；不得等待模型加载才能看内容 |
| 当前没有可靠偏好 | 使用中性候选，不自称精准推荐；原因在设置详情查看，首页不新增大段提示 |
| 模型未就绪/校验失败 | 保留可阅读候选，显示可操作的模型状态；不得自动转用付费云 API |
| 刷新中 | 保留旧卡片和锚点，来源状态更新；成功时间仅在新有效数据提交后改变 |
| 分批返回 | 首批有效热门候选不等待全部平台结束；空列表可先显示，已有列表通过“查看更新”接收后续批次。仍在请求的来源继续显示刷新中；末尾失败不制造重复更新，替换刷新不能丢失已提交的有效批次；离页/新一轮使旧延迟发布与迟到回调失效 |
| 局部平台失败 | 其他平台继续成功；失败平台保留标明时间的缓存，不显示假空榜或永远“正在刷新” |
| 推荐工作状态 | 紧凑状态圆点与设置详情表达状态，不在首页预留两行说明；无语义结果不称已准备，自动工作不改变当前列表位置。圆点保持可点击与无障碍描述 |
| 精排完成/兴趣变化 | 在安全提交点生成下一快照；用户正在滚动、反馈或看卡片时不插队跳动；用“有更新”轻提示应用 |
| 用户主动刷新/切换筛选 | 允许提交新顺序，明确开始新快照；不能混合过期 generation 的结果 |
| 没有高置信候选 | 不强凑“猜你喜欢”；保留当前可用内容和设置内调教入口，不在列表底部提供无限加载 |
| 更多候选 | 全量有效候选留在排序池，通过显式刷新换批；首页底部不追加，不用“查看更多”按钮；反馈历史仍可撤销屏蔽 |
| 切主题/字号、旋转、进程恢复 | 保留筛选、排序模式、阅读位置；不重复初始化所有推理任务 |

首页不显示科技/社会等分类或“按来源内排序”说明，题材可作为内部兴趣证据，不能据此恢复分类导航。来源内日期缺失不伪造时间。布局适配320/360/412dp、字号1.0/1.3/1.5、浅深色、TalkBack；保留48dp触控区，图标视觉可更小。

## 4. 模型与算法选择（固定方案，参数待验证）

### 4.1 模型事实、估算与验证区分

| 层 | 固定候选 | 查证事实 | 未证明的事项 |
|---|---|---|---|
| 初筛 | `BAAI/bge-small-zh-v1.5` INT8 ONNX | 约 23,954,432 参数；512 维；中文；MIT；社区量化结构与数据合计约 23,942,210 字节 | Android 实际峰值内存、延迟、量化损失、中文热搜命中率 |
| 精排 | `BAAI/bge-reranker-base` INT8 ONNX | 约 278,044,931 参数；中英相关性重排；MIT；查到 `Xenova/bge-reranker-base/onnx/model_int8.onnx` 为 278,825,308 字节 | Android 算子/ABI 兼容、实际耗电、偏好细分效果 |

二者模型文件合计约 302.8 MB（十进制），不是 App 最终安装体积，也不是 RAM。推理库、词表、文件拷贝、模型优化工作区额外计入。模型卡/文件索引只证明候选存在，不证明已能运行。

固定推理方式：首选 ONNX Runtime Android CPU + INT8，初始 1 个 inter-op、至多 2 个 intra-op 工作线程；以真机测试决定是否启用 NNAPI/XNNPACK，不能假定 NPU 自动可用。不在首版引入 Python、Node、Web 推理引擎或大聊天模型。

BGE-base 单模型、Qwen 0.6B 方案可作对照实验；用户未重新授权前，不把它们替换为默认交付架构。若已选模型实际不达资源/效果门槛，应展示证据并提出变更，不悄悄改方案。

### 4.2 正确模型输入输出

- 小模型：与模型卡一致的 tokenizer、Unicode 处理、截断、attention mask、CLS pooling 与 L2 归一化；查询前缀遵循上游建议并做对照，文档不能重复加查询前缀。
- 两模型的分词器不能共用一份实现就算适配完成。中文 BGE-small 的 BERT/WordPiece 与精排模型的 XLM-R/SentencePiece 路径分别核对；Android 使用可维护的 tokenizer 实现及固定词表，不能用空格切词或逐字 ID 代替。简繁、emoji、组合字符和长短文本要与上游逐项核对 token IDs、special tokens、mask、输出。
- 标题 + 来源已有短摘要为文档输入；初筛从最多 128 tokens 起测，避免为了填满 512 而抓正文。保留标题，不能让来源模板吃掉有效长度。
- 精排：偏好描述/正例构造的 query 与候选 title/snippet 成对输入，起始总长度上限 256 tokens；只取 reranker 的相关性输出，不当聊天模型使用。
- BGE reranker 是相关性模型，不保证服从“喜欢 A 但讨厌 B”复杂指令。正偏好与负反馈分开评估/约束，否定表达不能只靠相似度。
- 相似度、sigmoid 后分数不能直接叫推荐置信概率。依据留出集建立经验阈值/分桶，并保留“未知/证据不足”。
- 短标题信息不足时不得让模型补事实；可使用来源已有副标题/标签，仍不足则降为待探索候选。

### 4.3 本地推荐流程

`来源快照 → 中文与可读性检查 → 精确去重/保守事件归组 → 新内容向量 → 个性化初排 → 有界精排 → 时间/已读/规则约束 → 冻结阅读快照`

规则：

1. 硬排除（用户屏蔽对象/事件/来源）先执行，且可撤销；软负样本只降低优先级，不能全平台误杀。
2. 多兴趣桶保留代表性正样本，不把科技、生活、体育所有向量平均成一个向量。初版用有界最近邻/样本加权及阈值即可，不部署 ANN 服务。
3. 对每个候选记录匹配的兴趣样本、规则和模型版本。显式反馈权重大于隐式行为；未点击不能直接生成负样本。
4. 初排分数由正样本相似度、负样本相似度、有效时效、已读情况构成。权重、阈值属于版本化可调整算法参数，不能凭模型名称宣称已优化。
5. 精排只覆盖待展示窗口和不确定候选，按兴趣桶分配候选，避免单一兴趣垄断首轮；起始 30～50 是调度实验值，不是每天候选总量限制。
6. 未精排候选不能直接与另一个量纲的 reranker 原始分数混排。采用分阶段名次融合/已校准分桶；所有版本在相同候选上做回放。
7. 来源内名次可以作冷启动/同分裁决信息；不比较不同平台的原始“热度”单位，不内置“某平台天然更重要”偏好权重。
8. 跨来源重复话题不提高兴趣分或热度分；事件以代表内容/独立角度获得阅读入口。
9. 不按固定 80/20 比例强塞探索。探索数量受未知程度、可用候选与用户反馈影响，可减少，不能彻底锁死新兴趣。
10. 相关内容已读后可降权；有可验证新内容/重要更新时允许再次出现并标“有更新”，不通过抓取时间变化重置已读。

### 4.4 兴趣学习与缓存失效

精确少看降级补记（2026-10-24）：有效反馈中规范化文本哈希完全匹配的明确少看，应在模型未启动、模型不可用或向量不齐时继续软降权；不能被平台多看或弱收藏盖过。精确匹配集合独立于有界模型样本窗口，保留撤销/后来明确多看/过期/重置语义，不增加推理样本或变成关键词屏蔽。个人基础快照也应用该保护；按最新模式继续按时间，当前可见列表遵循冻结/查看更新规则。实现及验证见 `../validation/exact-negative-fallback-20261024.md`。

正负冲突实施补记（2026-10-24）：正向query的精排不能放大更接近负向兴趣的候选。没有正向优势（沿用已有0.03边界）时保留综合初筛位置，不用降低置信阈值或全局主题黑名单处理冲突；不增加推理对数。真实反例和守卫验证见 `../validation/interest-conflict-20261024.md`，不等于用户个人推荐质量已验收。

连续执行边界补记（2026-10-24）：模型进程释放后，后继首次连接须等待已知旧远程Binder实际退出，避免旧退役动作中断新一轮。等待可取消并计入原连接/前台时限，不以固定延迟、推理重试或后台重连代替生命周期协调。复现及验证见 `../validation/ranking-handoff-20261024.md`。

排序实施补记（2026-10-24）：真实100事件回放发现“中性档全部保留来源名次且不进精排”会丢弃非高置信但有效的相对兴趣信号。当前在同置信档内保留相对相关性，并允许有正向匹配的中性候选进入已有前40精排预算；同query仅同一档位融合，明确负反馈档不参与。仍不把相似度当喜欢概率。开发者测试画像的技术回放不得作为用户P@20或已满足第9节个人验收，证据见 `../validation/text-ranking-replay-20261024.md`。

- 冷启动可选一屏 12～20 个真实、跨来源候选，选择想看/不想看/跳过；这是一次操作规模，不是首页或候选上限。无选择也可正常阅读。
- 明确“多看”形成正例，明确“少看”形成软负例；“不要这个人物/来源”须明确作用域，不能从一次少看自动扩大。
- “事件看够了”只抑制 eventId 与已有内容版本；收藏是弱正反馈，保存待核实内容不一定喜欢。

合并反馈作用域补记（2026-10-24）：合并卡片的BLOCK须同时捕获当时合并编号及已知来源身份，已知同一URL更新元数据不得绕过永久屏蔽。ENOUGH捕获编号与各已知条目版本，仅旧版本隐藏，新内容允许返回。仍为一条反馈、一次撤销，不扩展为整个平台、共同关键词或未知未来相似报道的屏蔽；旧记录不猜补未知成员。实现及验证见 `../validation/grouped-feedback-scope-20261024.md`。
- 临时关注可设置期限/手动结束；长期兴趣不能因为几天没点就自动删除。临时过期不删除收藏。
- 点击、停留仅作弱信号并可关闭；后台停留、视频播放、登录等待不计兴趣学习时长；不收集全网浏览记录。
- 文档向量键：`模型版本 + tokenizer版本 + 文本规范化版本 + 规范化标题摘要hash`，不因来源别名或刷新时间改变而失效。
- 精排原始分数键：`精排模型版本 + 实际query输入hash + 实际候选输入hash + 规则/规范化版本`。画像或平台偏好变化应使最终排序快照失效，但不能无差别丢弃模型输入完全相同的原始分数；重新构造当前兴趣分组、负反馈约束和平台融合，仅对缺失的实际输入对执行精排。文档向量继续复用。
- 操作事件有唯一 ID、时间、来源、scope、撤销关系。撤销从剩余有效反馈重建画像，不能简单加相反分数造成漂移。

| 澎湃新闻 | 公开接口hotNews，非编辑精选/最新/广告 | 新增文字热门来源；正文按pageProps与contentDetail双重文章ID校验，拒绝用summary冒充正文；视频条目不进入推荐，未知类型/外链不混入；公开全文/图片/统一入口与升级已验证，账号/评论/长期稳定仍待验证 |
| B站 | 现有综合热门/排行榜多为视频 | 非当前扩源重点；不能用视频榜单充当文字热门供给；保留既有入口及不自动播放的兜底 |
| 抖音 | 热榜话题 | 后续来源适配，不作为当前文字推荐主线前置；保留既有入口，不预下载视频 |
| 百度 | 热搜 | 扩源目标；用户可关闭；不因旧争议擅自删去已允许来源 |
| 贴吧 | 热议/可证实热门入口 | 扩源目标；已有适配须重验，不能用任意吧最新帖冒充热榜 |
| 少数派、爱范儿 | 现有接口主要是最新/首页文章 | 单独标为“非热榜补充”，默认不混入核心个性化热搜；新增真实热门入口后再升级能力标识 |
| 小红书 | 现有发现页、个性化或点赞信号 | 后续来源适配，不作为当前文字推荐主线前置；不是已证实全站热搜，不冒充客观热榜 |
| 境外中文媒体/社区 | 有可靠热门榜/热门栏目时可用 | 能访问境外是许可条件，不等于所有新闻 RSS 自动进池；逐个完成来源契约 |

范围目标依最新澄清调整为：保留原五源，优先扩充可证实的文字平台热门内容，不再要求B站/抖音完整适配成为当前主线前置。原“至少8源、至少3个超出原五源”仅保留为候选覆盖实验目标，不得用视频榜单、最新RSS、低质量重复条目或失败来源凑数；来源数量本身不能证明推荐有效。需要明确记录实际稳定的文字热门来源、独立事件与候选覆盖、用户反馈后前排相关性，以及相对原五榜是否增加愿意阅读的内容。未取得上述真实证据不得宣称扩源有效；允许诊断版说明缺口，不用静态数据补满。

不默认接入 ScienceDaily、NASA、Aeon 英文条目；中文技术博客、BBC 中文等 RSS 曾验证可访问，仅说明网络可访问，不能算热搜来源已适配。

### 5.2 每个来源必须具备的契约

- `sourceId`、真实榜单名称/URL、`listKind`（TRENDING / POPULAR / LATEST / PERSONALIZED）、语言策略、内容类型、会话需求、条目跳转规则、请求/解析版本。
- `fetchedAt`、`lastSuccessAt`、`sourcePublishedAt?`、`sourceRank?`、原始热度文本及单位；不把不同时间字段混用。
- 榜单已提供的问题补充/纯文本摘要应随条目保留，用于卡片和有界模型输入，不能只留下标题而丢弃现成上下文。知乎当前已验证字段为 `target.excerpt_area.text`；只接受字符串、按现有600码点摘要预算保留，不额外抓全文，不以榜单摘要冒充完整正文或完整回答。
- 状态：READY / REFRESHING / STALE / OFFLINE / LOGIN_REQUIRED / RATE_LIMITED / UNAVAILABLE；错误可操作、超时可结束。
- 优先已适配官方接口/页面，遵循 HTTPS、来源域名边界；不绕过验证码、付费或账号权限。
- 网络请求原生层按现有机制复用相关平台 cookies；WebView 登录仍在原有会话中完成；不得把 cookies 发给模型。
- 普通网络源并行上限起始 3，动态 WebView 获取串行并受资源调度；平台间互不取消，关闭页面可取消其任务。
- 单来源有连接/读取超时、有限重试和失败退避；429 尊重服务端等待提示，无无限重试、无轮询唤醒。
- 用户手动刷新需发起有效再验证；HTTP 304 可以表示服务端确认未变化，但不得把未发请求的旧缓存伪装成新内容。

### 5.3 中文与去重边界

- 区分简繁中文，保留原文；英文产品名、数字和代码不判为英文文章。文本太短不能仅按汉字比例武断判定。
- 中文标题不保证正文中文：已知英文正文源拒收；信息不足时不能自动标为中文全文，来源资格测试要覆盖此情况。
- URL 正规化移除已验证的跟踪参数；保留内容 ID、分页、搜索和签名参数，禁止泛化删除所有 query。
- 精确同 URL/同平台内容 ID 去重优先；事件归组用标题、实体、时间与语义联合证据。仅语义相似不等于同事件。
- “同一产品不同问题”“同名人物不同日期事件”“同一话题的相反观点”不得强行合并；归组可拆分，并保留每条来源记录。
- 明确的动作状态属于事实边界：已经发生、未发生、计划发生和询问是否发生不能因模型高分合并。否定词须关联其修饰的动作，不能只比较标题中是否出现过否定词；普通“是否合理”等评价不自动当作事实尚未发生。验收须覆盖真实本地模型对状态相反标题给高分的情况，以及旧高分缓存不能绕过当前事实检查。2026-10-27当前实现只覆盖明确紧邻的动作及有限连接词，不宣称已完成通用中文语义解析；证据见 `../validation/event-predicate-polarity-20261027.md`。

## 6. 模块拆分、边界与逐项验收

各模块的“通过”必须由当前实现证据支持。模块表不是已经完成的任务清单。

### M00 基线整理与领域边界

- **输入/依赖**：当前版本、本文、现有回归测试、未接入 DiscoveryCore 草稿。
- **实现**：记录 git/安装包基线；梳理导航与阅读桥接；审阅草稿并明确移除/重写范围；引入新域模型与仓库接口，避免往 MainActivity 继续堆推荐代码。
- **输出**：迁移清单、目录结构、来源库存、兼容性测试入口。
- **边界**：本模块不发布新版本、不清理签名材料/历史未推送代码、不重置用户数据。
- **验收 A00**：旧安装升级数据仍可读；无未接入草稿冒充完成；正式开发引用本文；核心旧回归基线结果存档。

### M01 候选域模型与本地持久化

- **实现**：使用 SQLite/事务存储候选、事件、来源快照、反馈、画像、模型元数据、排序快照、向量索引、收藏；不要把全部文章/向量放进巨型 SharedPreferences JSON。
- **接口**：`CandidateRepository.upsertSnapshot(sourceId, revision, result)`、`queryCandidates(filters)`、`readSnapshot(id)`、`commitRanking(snapshot)`；后台 I/O，主线程只接收小分页结果。
- **边界**：推荐数据与平台 cookies 分离；数据库坏表/版本升级不得清会话；磁盘清理不能删除显式收藏元数据/偏好。
- **验收 A01**：事务中断无半份成功快照；重复请求幂等；过期 revision 不覆盖新数据；断网/重启可读缓存；迁移与磁盘不足测试通过。

### M02 来源采集与可读入口

- **实现**：每个平台一个 adapter，返回标准化条目、出处、状态、更新时间与能力声明；借用现有解析器而非复制；多源调度单独实现。
- **输出**：有效来源快照和失败状态，绝不向 UI 输出伪造文章。
- **边界**：模型不负责“编出新闻”；爬取受源规则和会话权限约束；不能用任意最新列表静默替代热门入口。
- **验收 A02**：第 5 节全部目标有实时结果；每源至少两次实际刷新、一次失败/断网回退；返回正确来源、可打开真实条目；原五源无退化；扩源门槛满足或明确未完成。

### M03 中文过滤、文本规范化与事件归组

- **实现**：清理来源 HTML/模板、保留事实标题摘要；精确身份去重、保守事件聚类；语言/内容类型标记可追踪。
- **输出**：文本hash、eventId、来源组、语言/不确定状态。
- **边界**：不改写新闻事实；仅凭相似度不得合并；归组不提高热度；新增不同来源不把已读变未读。
- **验收 A03**：覆盖简繁混合、英文术语、中文标题英文正文、不同事件相似标题、同事件不同角度；重复输入数量变化不提升事件排序；错误合并可回溯拆分。

### M04 模型资源与 Android 推理运行时

- **实现**：固定模型 revision、许可证、tokenizer、输入输出签名和 SHA-256 清单；使用文件路径加载，不把大模型通过 Java byte[] 复制多次；模型压缩/解压峰值单独测。
- **交付**：首个试用包提供可实际离线用的两模型资源（APK 内置或同次交付可验证离线资源包）；不得只写一个“下载模型”占位按钮。后续可改成明确的首次下载，断点/校验/回滚齐全。
- **供应链**：优先从官方权重可重复导出 INT8；社区量化作候选时固定提交与 hash，验证许可证、图结构和数值一致性。不执行不明 remote code，不把大权重提交普通 Git。
- **进程**：独立 `:ranking` bound service，非 exported；小批 IPC 只传文本/ID/结果，不通过 Binder 传大模型/整库；小模型与重模型不同时常驻。模型代码不访问账号、cookies，不发网络请求。
- **边界**：校验失败/不支持 ABI/算子/存储不足时保留来源阅读，提供重试/诊断；不得自动上传云端。
- **验收 A04**：Android16/API36 为主环境，API26/API35仅作兼容回归；arm64 实际运行（x86_64 模拟器仅辅助），原生库16KB页兼容；固定中文样本与 FP32 参考对齐；INT8 top-k 与参考偏差有记录；损坏/缺失模型可恢复；释放和重入无 native 泄漏/死锁；安装包无 Key。

### M05 语义向量、缓存与初筛

- **实现**：严格按 4.2 做 tokenize/pooling/归一化；增量编码、去重任务、有界队列；向量落盘，本地线性近邻在当前规模足够。
- **输入/输出**：规范化文本 → 512 维有限数向量；候选+画像 → 版本化初排结果及理由特征。
- **边界**：不编码全文/页面 DOM；空向量/NaN 不进入排序；相同文本只编码一次；操作排序不必重新编码。
- **验收 A05**：相同模型/文本命中缓存；改偏好不重编码候选；中文同义与困难负例对照；取消后旧任务不回写；1,000 条 float32 向量本体约 2.048 MB，额外索引/对象占用单独记录。

### M06 兴趣、反馈与撤销

- **实现**：显式事件日志 + 可重建画像；多兴趣桶；分开软反馈/硬规则/事件饱和；冷启动可跳过；用户可查看和删除兴趣样本。
- **交互**：反馈即时落盘和提示撤销；明确屏蔽可立即移除当前卡片并保留邻项锚点，其他项不全表跳动；小模型画像更新后下一快照生效。
- **反馈管理补记（2026-10-25）**：记录最近优先、内容/平台/弱参考分开筛选；长样本短预览并可查看全文/失效时间，单条撤销需在详情确认，不改变事件日志或排序算法。验证见 `../validation/feedback-management-20261025.md`，个人推荐效果仍需独立留出反馈。
- **边界**：单次点击不推断长期爱好；停留在后台/登录不训练；不能从阅读内容推断敏感身份属性作为用户画像。
- **验收 A06**：多看、少看、看够、撤销、临时过期、重置逐项回放；只影响正确 scope；重启一致；重置个性化保留平台登录、收藏与阅读设置。
- **跨进程局部证据（2026-10-25）**：内容LESS与平台MORE在实际停止进程后保留；来源更新时间刷新后精确少看保护仍生效，撤销只移除内容反馈且再次重启保持。成功链31/0，方法、首轮诊断错误和边界见 `../validation/feedback-process-restart-20261025.md`。不替代A06全部动作、非精确负样本泛化或用户推荐效果验收。

### M07 按需精排与融合

- **实现**：BGE-reranker-base INT8 处理候选窗口；query 来自可见兴趣样本/短描述；对精排原始分数校准/名次融合；所有任务带画像和源快照版本。
- **调度**：候选选择考虑可见/将可见窗口和不确定项，30～50 仅起始实验值；初版 batch=1 测峰值；同一兴趣版本、同一文本不重复推理。
- **边界**：不给已明确屏蔽条目翻案；不将正例语义接近自动当用户喜欢；不随页滚动无限跑全库；取消后能使用已完成结果但不能发布过期结果。
- **验收 A07**：能证实精排模型实际执行；同一候选集比较有/无精排，记录收益与CPU时间；全局分数不混尺度；正在阅读的顺序不重排；精排故障安全回到初排并可诊断。

### M08 内存、电量与生命周期调度

2026-10-25实现补记：修复五秒PSS缓存跨进程集合变化复用的问题，真实模型服务新增/退出专项8/0、当前混淆推荐/阅读20/0；见`../validation/memory-process-set-20261025.md`。同UID公开PSS仍为下界，不代替独立WebView和Find X7 Ultra整体峰值/耗电验收。

- **实现**：统一 `RecommendationScheduler` 协调采集、初筛、精排、正文预取；优先级为当前阅读/登录 > 用户明确刷新 > 当前推荐准备 > 可选预取。
- **输入**：前后台、滚动/触控、页面类型、屏幕、电池省电、热状态、memory trim、队列版本。
- **动作**：暂停新推理、完成/中断当前小任务、销毁会话/结束独立模型进程、取消过期队列；不可仅调用 stopService 就宣称进程内存已释放，必须实测。
- **边界**：后台无循环工作/周期唤醒/持锁；退出 App 不继续耗电；已有 ArticlePreloader 不得和精排争用隐藏 WebView。
- **验收 A08**：第 8 节资源门槛；快速切前后台、开网页/视频、低电量、高温、内存 trim、Binder死亡都可恢复；主 UI 不等待 native 推理取消。

### M09 阅读卡片首页与来源管理

- **实现**：原生可回收列表（可引入 RecyclerView），避免几百个常驻 View；冻结快照与稳定 eventId；实现 3.2～3.4 所有状态。
- **来源管理**：开启/关闭、进入平台榜单、登录入口、更新/失败信息；停用来源只影响候选展示，不清 cookies、不删除收藏。
- **边界**：不保留固定五平台底栏占用新首页；不恢复旧总榜文案；来源筛选不等于偏好权重；不因为原型只画 3 条就截断。
- **验收 A09**：按修正后的第二变体核对；小屏/大字号/暗色无裁切；触控、TalkBack、滚动流畅；刷新/反馈/打开返回不跳动；用至少100个实际候选的排序池验证不同换批，首页保持有限一批且无无限加载，不把原型前三条变为推荐上限。

### M10 阅读、登录与旧保存数据兼容

- **实现**：选定source entry交给现有阅读/来源适配，保留cookies、来源模式、问题/帖子身份与阅读位置。历史保存数据中的eventId/原来源身份/标题快照保留迁移兼容，不恢复稍后读入口。
- **边界**：摘要不能当全文；无法提取时提供实际来源页；登录只能解决源实际允许的问题，不能承诺绕过付费/风控；视频不自动播放。
- **验收 A10**：知乎补充/回答续读、微博刷新、V2EX hot、既有来源手机布局、登录双向滑窗、同源登录返回及来源失效后备用入口；旧保存数据在失榜/离线/升级中保持兼容，不增加入口；不得出现重复折叠/下一条按钮。视频型来源非此次文字主线的扩展重点。

### M11 可解释设置、隐私与本机诊断

2026-10-25实现补记：本机推荐详情已汇总有效模型回报的向量/精排条数、推理与加载的进程CPU和墙钟时间。未知计时明确标记，缓存命中不算新推理；仅已回报模型工作，不代替整个App能耗/RAM或未完成任务测量。真实混淆详情20/0及状态11/0见`../validation/model-work-usage-20261025.md`，不据此关闭A08/A11整体门槛。

- **实现**：来源/偏好/模型状态可查看；显示“本地推荐，不使用云端 AI”，区分普通新闻网络请求；诊断含模型/规则版本、缓存命中、任务数/CPU时间、故障原因，不显示用户私密原文。
- **边界**：本版不引入 Key 输入框作为推荐前置；不自动开启 DeepSeek；调试日志不含 cookies/凭据/账号存储；用户清缓存不等于清偏好/退出登录。
- **验收 A11**：断开模型服务网络仍可本地推荐；无云 AI endpoint 请求；诊断能区分初排/精排/降级；清缓存、清画像、清收藏三种操作范围明确可测。

### M12 升级、异常恢复与安装包

## 8. 资源、电量、缓存和调度详细边界

### 8.1 内存计量与目标

- 统一采用十进制 MB：1 MB = 1,000,000 字节；工具给 KiB/MiB 时在报告换算并保留原值。
- 总占用计量为本 App 主进程 + `:ranking` + 本 App 所属 WebView renderer 等进程的合计 PSS；记录各进程 PID、PSS、native/Java heap、峰值 RSS 作辅助，不遗漏模型进程。
- 以下为开发目标，最终数值必须真机验证；目标手机为用户确认的 OPPO Find X7 Ultra、Android16 / ColorOS16，按12GB物理RAM；系统补丁版本、实际页大小和硬件指标须在真机报告记录。

| 场景 | 合计 PSS 开发目标 |
|---|---|
| 已缓存首页、模型未加载 | 尽量 <350 MB |
| 初筛 | 尽量 300～500 MB |
| 集中精排 | 尽量 600～900 MB |
| 高负载目标 | 整个App约1,000MB；用户接受短暂约1.2GB峰值，须记录持续时间与回落，不因机械卡阈值损害体验 |

- 小模型和重模型顺序加载、释放；推理进程退场前验证实际 PSS 下降，不把 `System.gc()` 当内存控制方案。
- 大页面/视频/登录加载前抢占精排；保留已算结果，禁止等所有候选推理完才响应点击。
- 内存压力软阈值起始按 850 MB 预算，结合 `onTrimMemory` 与系统内存状态提前退让；不要高频调用 PSS 接口本身造成耗电。
- 系统/WebView有异步峰值，不能保证任意网页绝不超出目标。持续高占用或无法回落要定位并报告；短暂约1.2GB已获用户接受，不伪造严格1GB达标，也不牺牲体验硬压峰值。
- ROM允许长期超过2GB（含安装包、模型、缓存及其他数据），要求持续淘汰无用缓存。独立150MB/300MB缓存限额已取消。保留LRU/队列/低磁盘保护，按全App计量；不得隐藏模型和安装包占用。

### 8.2 推理与网络调度

| 事件 | 允许工作 | 必须停止/避免 |
|---|---|---|
| 首页前台静止 | 增量采集、初筛、按预算精排 | 全库反复编码、无上限精排 |
| 列表滚动/连续触摸 | 读缓存、UI、当前可见加载 | 新重模型任务；正在执行单项尽快归还控制权 |
| 阅读/登录/播放 | 当前来源请求、原读者功能 | 精排、隐藏动态榜单和非必要正文预取争抢 |
| 切后台/熄屏 | 必要状态持久化 | 后台 AI、周期拉榜、定时唤醒、持续 wakelock |
| 省电模式/低电量 | 缓存、基础排序、用户请求 | 自动精排；低电量阈值初始20%，作为可调开发参数 |
| 热状态升高/内存 trim | 保留当前阅读、释放模型 | 自动重启模型；需冷却/状态恢复再允许新任务 |
| 网断/弱网 | 本地候选和模型 | 无限重试、平台失败拖住其他成功来源 |

- API29+ 使用公开热状态回调，旧版本用公开可用信号采取保守策略，不读隐藏温度路径；不把缺少温度数据记为“温升通过”。
- 初始推理连续计算时间片以 2～3 秒为调参起点，任务粒度至少到单候选；计量 wall time 与 CPU time，达到预算就让出，结果可继续用。
- 默认无后台定时刷新、无通知、无开机启动。前台来源有新鲜期，手动刷新可显式再验证；不得用频繁轮询模拟实时推荐。
- 不固定每次只缓存/推荐前三条。数据元信息增量缓存与大全文预取分开：前者覆盖有效候选，后者受阅读预测和资源调度限制。
- 分批候选已经可读时，普通榜单尚未全部结束不应单独阻止正文预读；仅在采集名额空闲时允许一个串行预读管线，三个榜单名额占满时继续让位。已排队或正在执行的浏览器榜单阻止新预读，浏览器启动前暂停正文/图片预读，结束后按当前窗口恢复；仍受前台、交互、温控、电量、磁盘和模型互斥约束。这是调度预算，不以取消瞬间的socket数量或模拟器结果证明真机峰值。
- 预取失败、短时间切页、源未变化不能重复申请整轮模型工作；模型加载次数也要计入耗电成本，避免频繁销毁/重载震荡。

### 8.3 电量评估与验收口径

用户没有指定耗电数字，以下是开发方的初始质量门槛，不是已经测出的结果；经实测可调整，但必须记录理由，不能删除失败结果。

1. 真实手机、非模拟器，断开充电，固定亮度/刷新率/网络条件/起始电量区间，温度恢复后开始；不把充电或不同网络试验混比。
2. 三模式对照：A相同App/候选/页面无模型，B只初筛，C双模型。使用固定30分钟阅读脚本，分别覆盖冷缓存和暖缓存，按交错顺序各重复至少3次。
3. 脚本包括刷新、滚动至少100候选、进入/返回多篇、一次平台登录页与一段媒体阅读；用同一组页面/网络回放隔离推荐计算差异，真实网络另做验证。
4. 记录能量/电荷计数（设备支持时）、CPU active time、任务/加载次数、网络字节、PSS、帧时序、热状态；百分比电量条只作辅助，不能用1%的跳变声称精确节电。
5. 初始目标：暖缓存C相对A的30分钟能耗中位数增量<=10%；冷缓存首次计算增量<=20%；超过目标先检查缓存/调度再优化。测量误差覆盖增量时标“无法判定”，延长测试或补硬件计量。
6. 切后台/熄屏后10秒内无持续模型CPU活动，排空/取消队列；后台30分钟无周期唤醒或推荐轮询；返回可继续使用已有结果。
7. AI开启不应持续把设备热状态推到MODERATE及以上；热保护触发时暂停重模型。在相同初温的对照中若出现可重复的额外热节流，不能宣称均衡模式合格。
8. 模拟器可验证状态机、取消与进程回收；不能替代真机能耗、ARM推理性能和体感发热验收。没有可用真机时，这些验收保持未完成。

### 8.4 交互性能门槛

以下也属于待真机验证的开发目标，必须标明冷/暖启动条件。缓存内容能否及时出现不得依赖网络或模型先完成：

- Activity 可见到首屏缓存卡片呈现的 p95 <=800 ms；无缓存时500 ms内提供明确加载/离线状态，不等所有来源才显示第一个成功源。
- 反馈、收藏、打开阅读等触控到本地可见响应的 p95 <=100 ms；网络获取正文耗时单独报告，不能混入该指标掩盖UI卡顿。
- 滚动期间不启动新精排任务；AI开启相较关闭的慢帧比例增量目标<=2个百分点，采用相同设备、刷新率、候选与操作脚本，记录实际帧时序。
- 点击进入阅读或切后台后立即停止排新任务；单项取消/推理进程退场不阻塞主线程，异常长任务有可结束的独立进程边界。
- 当前版本存在的页面重建、缩放循环、滚动锚点跳动属于功能错误，不能用平均帧率合格豁免。

## 9. 推荐效果的验证与质量门槛

### 9.1 不把“跑通模型”当“推荐有效”

- 技术样本：真实中文热搜固定快照，含不同平台、短标题、谐音/梗、中文与品牌混写、体育/社会/生活/科技、同事件多来源、相似但不相关、立场不同等。
- 个人效果样本：由用户明确标记想看/不想看/不确定；只有用户选择才是“他想看”的依据，开发者或另一个模型的判断不得冒充。
- 按事件和时间切分学习集/留出集，不能同一事件多来源分别落到训练和验证以制造高命中；评价集不能用于反复调阈值后仍称独立验证。

### 9.2 指标

技术三顺序记录补记（2026-10-25）：公开固定池真实模型回放已可记录同一候选/画像/向量的中性、初筛、双模型顺序与版本。记录明确为developer、无标签且非独立留出，不能作为本节个人指标；6/0及数据链边界见 `../validation/three-order-capture-20261025.md`。

开发侧计算工具补记（2026-10-25）：固定画像的独立事件/时间留出、三模式相同候选配对和未知标签处理已提供离线工具，协议与8项测试见 `../validation/recommendation-evaluation-tool-20261025.md`。当前只有合成公式校验，没有用户标签、个人P@20或真实双模型收益证据，不因此通过本节门槛。

| 指标 | 定义/用途 |
|---|---|
| P@20 | 前20个不同事件中用户明确想看的占比；不足20必须同时报告分母，未知标签不作喜欢或不喜欢 |
| 明确负反馈复现率 | 同一作用域、未撤销且未出现实质新内容的负反馈在后续前排再次出现的比例 |
| 漏选抽检 | 从未进前排的有效候选随机抽样让用户选择，估计被遗漏兴趣；不能把该估计称全网召回率 |
| 重复事件占位率 | 前20个位置中同一事件重复占位比例；独立角度按人工检查记录 |
| 双模型增益 | 在相同候选/画像下，C双模型相对B初筛的P@20和漏选变化，同时列CPU/能耗增量 |

初始试用目标：至少5个不同会话、累计>=100个前排候选有用户标签；相较中性平台候选基线，P@20提高至少15个百分点作为继续迭代目标，同时检查漏选与来源覆盖。它是验收试验目标，非向用户保证的上线准确率。

双模型价值门槛：留出集有稳定增益（初始参考为P@20增加>=5个百分点，样本不足则不下结论），且能耗/内存达标。若不达标，应保留证据、优化精排输入/调度或提出方案调整；不得把仅有小模型回退的试用版写成双模型效果已验收。
