## 模块与实施顺序

1. 真实曝光识别：列表卡片有效可见面积至少50%，连续停留至少1200ms才算本轮看见。阈值为初始工程参数，不宣称经过用户效果验证。只是抓取、缓存、模型排序、绑定列表行均不算曝光。快速划过不算看见；遮挡/切后台/离开首页中断累计。一个展示周期内同一事件只记录一次。使用单个有到期时刻的回调，成熟后即停，无周期轮询。
2. 有界本地记录：区分曝光和已有效阅读，不将未点击转成负面兴趣反馈。事件与成员身份用已接受的合并关系关联，不能按含糊标题把另一个事件降权。保存近期记录并有条数与时间清理；曝光变化不能让模型缓存和兴趣版本失效。数据库迁移保留账号、反馈、历史与模型结果。
3. 显式更新换批：只在用户更新时调整当前批次，不在阅读中自动替换。先执行现有语言/视频/来源/用户排除规则与兴趣质量分层，再在相同质量层内优先未见内容。近期见过和有效读过的逐步后移，不能跨越明确低兴趣/负反馈保护层。旧内容可回补，新内容不足不强行凑批。连续点击去重/取消旧任务，离开即停止。
4. 重要进展重新入选：仅有新标题、缓存时间变化、名次上涨、重复转发都不能自动作为进展证据。优先明确补充、后续报道、正文/讨论的实质新信息；无可靠证据时保守保留冷却。模型仅辅助必要比较，复用已有结果并限制每次工作量。此模块须独立验证，不以“已曝光”表实现完成冒充进展识别完成。
5. 内容供给评估：先用现有来源验证重复率与实际阅读收益。只有供给不足证据成立时再评估平台热门讨论/近期文章的接入；免费可读、中文、文字优先、真实登录共享等原门槛不变。此次同意不代表无界全网搜索或立即加入任何新平台。
