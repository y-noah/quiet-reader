# 预读转前台继续沿用短时限：修复与对照

## 已确认缺陷

ArticlePreloader.promote仅替换接收者，DynamicReader仍保持后台预读的14次/22秒及非显式解析模式。贴吧话题先取列表再转实际帖子，延迟正文会在用户已打开的情况下过早结束。原本直接前台打开同类页面已有28次/40秒预算；此缺陷是两条路径行为不一致，不认定为真实虎扑登录故障根因。

DynamicReader增加前台接管，复用当前WebView和正在执行的请求。慢来源最多从原始取得开始计40秒，重新绑定回调不续期，不复活已到期/已结束任务。会话替换读取继承同一原始开始和绝对截止时间；已取消/销毁路径不变。显式解析标志在采样时冻结，接管前正在解析的结果不能以旧模式交付，会在同页重新采样；原有效best保留，避免临近时限丢弃已取得文字。原生预读尚未转WebView时就被接管，后续动态读取也直接采用前台策略。未打开的后台预读仍14次/22秒，不增加后台工作、平台或模型。
