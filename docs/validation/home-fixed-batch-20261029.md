# 首页固定 20 条与刷新绘制结束确认

后续用户明确不要求20条，现已由[首屏加一次自然上滑](home-one-swipe-20261029.md)的按实际高度取批方案覆盖；以下为本轮原始历史证据，不能再当成当前条数需求。

## 用户最新要求及本轮边界

首页每批最多 20 条，到底不再追加，通过刷新换批。用户进一步明确动画问题是“内容已经换好，动画还在转”。本轮仅使用专用模拟器，没有再次操作已交还的手机；真实设备是否已解决该反馈仍待确认。

## 实现

新增 FeedBatch：来源过滤后截取前 20 条作为本次展示，完整排名池及持久快照保留供后续刷新。删除 Activity 的 40 条初始可见额度、到底追加 40 条的任务、旧 visible 保存/恢复状态。候选不足 20 条时照实显示，不补重复项。预缓存依旧随前台操作工作，首页上限不截断排名池。

刷新按钮统一进入 Controller 的刷新入口，不再依赖 Activity 上一次 updateAvailable 值决定是否调用一个可能已无 pending 的分支。显式刷新成功接受列表后，Controller 等待 Activity 的实际 OnDraw 确认，再结束本轮 busy。OnDraw 回调将结束动作投递回主线程，在该次绘制调用返回后执行；没有固定转动时长、定时强停或等待全部采集/模型/预缓存。取消与失败仍立即结束，旧请求由 epoch 拒绝，离开页面或停止时移除监听。

这补强的是内部发布与实际绘制的边界，不把它宣称为已经在用户手机复现了此前持续转圈的根因。前轮普通包最终恢复圆点的检查不足以覆盖用户整个观察窗口，本轮专门阻止新画面绘制后再放行。
