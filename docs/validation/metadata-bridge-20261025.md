# 完整元数据与纯标题热榜桥接

对应晚间重复事件反馈。全部测试与安装只针对电脑 API 36 模拟器 emulator-5560 的 discoveryprobe 隔离包，未操作手机或普通包，没有提交、推送、改默认版本或发版。

## 行为和身份

- 同一北京时间日期、规范后的实质标题一致，且候选中只有一组完整精确证据时，纯标题、重复标题摘要、或摘要完全一致但缺少发布时间的条目可加入这组。完整证据仍采用原始标题/摘要/UTC 日期身份；原候选 ID、原 URL、热度原文不变，不叠加热度。
- 非空新摘要不会仅因同标题就桥接到完整摘要。出现两个不同完整精确证据组时，不让纯标题把它们连接起来。V2EX 已知线程不参与这种标题桥接。跨日、事实变化及数字保护继续生效。
- 先确定桥接关系，再按成员和事件反馈过滤。否则先删除已屏蔽的完整成员 ID，会令纯标题重复条目漏出。
- “分开显示”现在使用与事件屏蔽相同的有界成员捕获格式，保留完整侧和弱标题侧的原身份，一次反馈、一次撤销。完整条目离开热榜后，弱标题仍维持分开；弱标题离开后，完整成员也保持分开。FeedStore 的长目标例外新增 SEPARATE/event，来源/样本等范围和坏格式仍不获得例外。
- 新合并卡片的屏蔽及“看够了”捕获两侧已观察身份，因此完整成员离开后，已捕获的弱标题家族仍受反馈约束；原成员变更元数据的永久屏蔽继续有效。仍优先保留全部成员 ID，额外别名服从原5001目标预算。
- 不为每条完整记录永久添加一个宽泛标题别名。这样不会把同标题、不同实质摘要的完整事件无条件关联到另一事件的历史反馈。旧反馈在共观察关系仍存在时继续生效；若只剩旧完整组哈希、完整成员也已消失，又从未捕获弱标题侧，不伪造该未知关系。

## 推荐评估链路

新增可选的 identity_aliases 哈希集合到真实预排序来源记录，校验其与候选成员的静态别名一致。旧冻结记录缺字段时保留原范围，不重新计算旧数据。

前瞻消费同时保存显示事件、各成员 ID 及安全静态别名。原完整/弱成员都离开活跃快照后，同一弱标题换 URL 不能再次作为新样本。候选选择也检查全部安全别名，避免旧包装主键绕过已消费记录。分组策略版本为 headline-metadata-bridge-v3，旧准备需要重新建立。

Python 只读导出保留经验证的别名哈希，不新增标题、URL、Cookie 等私有内容。人工审阅模板包含别名，要求一个冻结组的成员及别名映射到同一人工事件，禁止静默拆分以改善评估数据。上述机制仍不自动证明独立本人推荐质量。

## 保留边界

这是精确实质标题的受控桥接，不是不同措辞事件的语义去重。多个完整证据组即便其实属于同事件，也仍保守分开；真实标题集合的漏合并/误合并质量尚未验收。真实来源鉴权、贴吧实际图片矩阵、旧视频缓存及真实媒体流、Find X7 Ultra整App峰值/功耗/温度、空间提示、本人推荐质量和最终发行门槛继续开放。
