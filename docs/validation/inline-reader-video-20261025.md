# 文字正文内嵌视频：实现中记录

对应晚间反馈中的文字流视频附件。不是完成/发版报告。

## 本轮实现

- 解析器在剥离来源播放器 HTML 前，记录视频在正文中的结构位置。使用经过验证的 URL/封面的稳定散列身份，不使用会在追加回答时改变的数组索引作为存储身份。复制、历史恢复及附件列表重排均有单测。
- 不信任来源自带的私有标记，不让推荐/引用播放器冒充当前附件；保留引用文字。只有媒体的区段不创建虚构正文或回复。纯视频主题的默认过滤保持原逻辑。
- 已定位附件在原位置显示原生 HTML video，preload=none，初始无 src，无自动播放。受限/未知来源附件是紧凑来源链接。原始媒体 URL 不进入阅读页 HTML；只有点击后生成临时同源流地址。
- 受控流请求只接受当前点播的地址，经已知来源媒体域、HTTPS 和公共主机校验后转发；共享对应媒体域 Cookie，并使用原文 Referer；支持单段 Range，不自动跟随不可信跳转，不缓存视频文件。切换/后台/退出关闭请求。
- 实现全文播放器显示/退出回调、实际错误或 20 秒未准备好的紧凑回退、主动重试。尚需验证这些行为后才可验收。

## 当前证据

`inline-media-build2-20261025.txt` 构建成功，484 个 JVM 测试无失败/错误/跳过。后续 build3 只更新测试驱动逐阶段输出及截图。

第一次结构改动测试发现 5 个失败：媒体单独产生区段，破坏空首楼/空问题与回答身份。已改为媒体区段必须有真实文字或图片，否则保留附件但不创建正文，保留原有边界测试。原文本测试改为区分结构视频块与文字，新增位置/身份/持久化/注入/引用及纯媒体测试。

真实 WebView 测试 `inline-video-flow3-20261025.txt` 目前只完成三项：打开缓存正文、实际 DOM 两个无 src/preload=none 播放器、打开后零视频传输请求。首次主动播放时模拟器 QEMU 退出，测试没有终态成功。Windows Application Error 记录至少一次 qemu-system-x86_64-headless.exe 访问冲突（0xc0000005）。不是 App Java 异常通过，也不是正常完成。

尝试关闭 VideoPlayback 特性后发现本地配置文件明确它是相机视频回放，不能据此声称启用了软件视频解码；该脚本选项已移除。后续改用原启动脚本支持的 host 图形后端继续诊断，尚待结果。

## 后续修复与最终本轮结果

以上“未验收”是排查早期状态。本轮已补足本地实际播放器链路，真实来源与真机门槛仍开放。

host 图形后端避免了前面的 QEMU 退出，但实际状态诊断显示视频 readyState=4、duration=5.055、time=0，play() 为 NotAllowedError。不是下载或解码文件缺失。WebView 媒体手势策略必须在自有文档加载前设置；改为创建正文 WebView 后、loadUrl 前设置。仍由原生显式点播操作挂载临时媒体地址，打开正文不提供 src、不自动播放。保留点播期间的自有脚本运行环境，HTML 的 CSP 不允许来源脚本，未增加 native bridge。

`inline-video-flow8-policy-20261025.txt` 首次实际播放/暂停/切换/失败重试/Home 释放 11/0。全屏测试初次坐标点击未观察到回调；五秒素材也在较长触摸流程中自然结束，导致后续断言混淆。保留 flow9～12 的失败记录，给交互阶段使用循环素材，正常结束另设独立检查，并优先取得系统可访问性控制节点再触摸原生全屏按钮。最终明确观察到 document.fullscreenElement=true，生产 WebChromeClient 创建真实全屏窗口，系统 Back 返回的是同一 WebView，未用直接调用回调代替用户操作。
