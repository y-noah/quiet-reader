## Android16 / 原生分词更新

- 现成Extensions0.13.0的ARM64库只有4KB对齐，Maven没有更新的Android制品。因此移除Android Extensions依赖，直接从固定官方SentencePiece提交 `31646a467d2051eb904e0b45de3a73e91fe1c1e3` 用NDK28.2.13676358/CMake3.22.1构建；源码tar SHA256固定，构建前核对未修改源文件。
- JNI显式UTF16→标准UTF8，保留字符串长度；此前NUL截断/拒绝边界已消除，原来负例现在也和HF原始token IDs完整一致。
- 原生四种ABI成功编译；APK内ARM64/x86_64全部ELF LOAD对齐16384，`zipalign -c -P 16 4`通过。这是二进制兼容前置检查，不是16KB ARM真机运行结果。
- API36官方稳定x86模拟器报告Android16、4096页；`android-api36-native-parity.txt` 62项、`android-api36-native-lifecycle.txt` 14项全部通过。
- API36首次用adb写外部目录的诊断导入出现EACCES，保留 `android-api36-external-import-failure.txt`；改为正式离线资源打包路径 `-PbundleLocalModels` 后安装、hash校验、模型执行全部通过。不申请宽泛文件权限，不依赖adb目录权限作为正式功能。
- 已签诊断包SHA256/大小/ELF检查见 `artifacts/local-ai/android-api36-package.json`：325,365,063字节，包含307,948,507字节模型资源（含清单）。设备私有目录解包、系统安装文件和原生库仍另占空间，不能称总存储仅325MB。
- 当前运行文件白名单307,946,109字节。模型本身不算数据缓存，但必须计入总存储报告。
- 该轮API36直接探针精排后采样399,984KiB PSS；仅为该进程采样，不是全App峰值/手机性能。保留每个ABI和系统的差异，不把API26较高值删掉。
- target36的系统返回已改用OnBackInvokedDispatcher。`android-api36-system-back.txt` 7项通过：实际BACK事件返回阅读列表、退出顶层、来源WebView历史返回和根页退出；来源内容为受控合成页，不能当平台登录验收。

## 版本与复现

- 基线 0.3.35 / code46；本次未递增版本。
- ONNX Runtime Android 1.23.2、Extensions Android 0.13.0；CPU 2 intra / 1 inter 线程，关闭 arena / memory pattern / prepacking。
- 模型上游、量化 revision 和运行文件 SHA256 固定在 `app/src/main/assets/local-ai-manifest.json`。
- 运行文件白名单共 **307,946,591 bytes**。包含两模型、词表与 SentencePiece graph，不是安装占用；APK和私有目录拷贝另计。
- Python 工具：`scripts/models/prepare_models.py`、`verify_models.py`、`compare_quantization.py`。
- Android 构建：`scripts/models/build-probe.ps1 -Offline`。只在项目模拟器安装诊断包。
- 分开执行 `LocalAiInstrumentation` 的 `-e mode parity` 与 `-e mode lifecycle`，不得同进程先跑直接模型，再把残留 allocator 带进服务内存试验。
- 最终产品只允许 `:ranking` 服务加载模型，主界面调用 `RankingClient`。当前尚未接入首页。

API26 合并测试错误地同时保留了直接测试进程的原生分配与独立推理进程。拆成新进程后通过，但这一发现本身仍说明 `OrtSession.close()` 不等于实际归还全部PSS。不能用GC代替独立进程退出。

数值事实：小模型8个向量的FP32/INT8 cosine约0.9919～0.9946，最大单维差约0.02082，部分近邻次序变化。精排最大logit差约0.74086，两个相关/不相关配对顺序保留。参考来自同一固定社区仓库的FP32图；尚未对原始PyTorch权重做独立导出一致性验证，不能混称“官方原始模型已全量对齐”。

## 分词与输入边界

- 原生BERT组件在未知词回退、组合字符、特殊标记处不同；改为Java `BgeWordpiece`，保留固定上游词表与cased配置。
- 精排SentencePiece需要包装HF added tokens；`<mask>`左侧空白按上游处理。
- 加入简繁、品牌混排、emoji、组合字符、私用字符、空串、特殊标记、长文本、pair截断、控制字符测试。
- **内嵌NUL**会使原生SentencePiece字符串边界静默截断。精排入口明确拒绝，保留原始HF oracle作为负例，未删去该测试。候选规范化去除无效控制字符，之后才建立文本hash和模型输入。
- 测试结果仅覆盖固定样本；Android Unicode版本与罕见字符仍是需要扩充的边界。

## 内存证据的范围

API35早期直接探针精排阶段PSS约423,463～432,682 KiB；API26新一轮约675,754 KiB，卸载后仍约675,674 KiB。均为单个测试进程的阶段采样，不是连续峰值，更不是包括阅读器/WebView的全App占用。不得据此向用户承诺手机一定省电或小于1GB。

服务使用非exported `:ranking`、小批Messenger IPC、单串行工作线程；输入<=48条、<=50,000字符，起始时间片<=3秒（模型加载单独计时，单项可越过时间片）。结果携带generation/profile/source版本。取消请求先终止native run并中断工作线程，随后仅结束自身ranking进程。空闲8秒退出，客户端必须解绑，验证无BIND_AUTO_CREATE重启循环。
