## 对实现的影响

楼中楼有可靠绝对时间基础，不能笼统认为贴吧没有时间证据。这个公开端点本次不提供顶层楼层创建时间，因此不能把子回复时间移给父楼，也不能把抓取时间当发帖时间。当前生产仍不支持贴吧讨论进展重推，不能拿这份审计说接线已完成。

后续实现须保留以下边界：

1. 先验证请求的实际帖子/当前页和已有正文归属、账号及缓存scope；按thread_id+post_id+comment_id三重身份附到已经解析的楼中楼，拒绝未知父楼、重复冲突ID、登录/错误响应、字符串/浮点/未来时间。
2. 时间只附楼中楼，父楼/主帖不借用；继续保持父楼和楼中楼分离，不根据“回复某人”文本推断父子关系。
3. 当前DOM没有现成epoch，若需额外来源请求，只允许在已有的前台获取/刷新/续载动作内且确实取得稳定子回复时触发。须限制并发、响应字节、每scope/page请求次数和超时，并复用同次结果；关闭、换账号、失焦/后台和取消后不发布结果。来源失败不能挡住已可读正文。
4. 不导入user_list或原文进入进展历史，只保留版本化时间/身份和既有hash。不能把普通楼层当成有可靠时间的新进展；不能开启全历史或末页轮询来补时间。额外流量、CPU与取消成本需实际测量，不能仅因有端点就加入所有预读任务。
5. 修改之前先冻结真实字段结构及三重身份回归样本，再验证源snapshot、解析/历史缓存、虚拟分页合并与显式推荐刷新。需覆盖父楼缺失、楼内编辑/旧页/复制正文、权限变化、response迟到、再次曝光消费与R8；不降低新信息门槛。
