## 本轮发现并修复的产品缺陷

320dp/150%字号下，受控贴吧短帖内容高559 CSS px、可视高522 CSS px；滚到底仅37 CSS px（111原生px），未达到旧滚动触发 y>dp(100)，因此到底也不会自动加载。此前只给完全放得下的短页做了定时检查，未覆盖这个略微溢出的区间。

生产修复：向下滚动即检查接近底部条件，不再要求滚过100dp。maybeLoadMore 原有并发、生命周期、账号/缓存、还原阅读位置、失败暂停和续读资格检查不变。不是改测试跳过该短页；同一个受控场景在修复前超时，修复后实际 loader 收到请求并追加成功。

## 测试驱动迁移与原失败证据

- 普通续读改为真实 WebView 向下滚动，不再寻找已移除的正常“查看更多”链接。
- 错误重试仍用真实触点点击。第一轮坐标落到窗口外；诊断显示恢复原段落的异步滚动把按钮移出屏幕。驱动等待恢复/抑制期结束，并在按钮实际可见时才注入触点；不能用反射 loadMore 代替错误恢复操作。
- Accessibility 查找尝试未取得 WebView 重试节点，不以此声称完整辅助功能通过。
- 知乎快速回调锚点用例属于合成即时回调测试，准备位置时暂停自动触发，避免它自身开启真实来源请求；不把该用例宣称为真实知乎自动续读/登录验收。
- 视频过滤后的正常脚注已按用户要求取消，测试改验过滤账本和实际视频/正文DOM，不再要求解释性文案。

保留 geometry / accessible / settled / auto-diagnostic 等失败日志。auto-diagnostic 在46项后精确记录上述短帖111px滚动与超时；不能把之前失败写成全部通过。
