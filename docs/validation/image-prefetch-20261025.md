# 正文优先的配图主动缓存 / 2026-10-25

## 本轮实现

上一轮只能保存已经请求过的图片。本轮在发现页的真实正文预读窗口接入 ImagePreloader：当前条目向前16条、向后4条，正文队列空闲后才启动配图获取。按窗口顺序先取各篇首图，再取第二、第三图；每篇最多选3张正常正文图片，包含知乎初始展开回答的图片，跳过后续未展开回答、回复/评论图片、行内表情和已知视频附件/封面。窗口随滚动更新，不限定前三个话题。不追抓下一页图片，不下载视频。

独立可取消请求队列串行获取，不创建额外 WebView、不解码 Bitmap。每轮最多6秒、8MiB取得预算，单次主动网络响应最多1MiB；失败按该次预算计费，避免连续大图失败无限取数。缓存命中读取可能大于主动网络单图上限，但不额外保留在RAM。前台正常读图仍保持原8MiB请求上限。以上为本轮投机工作保护参数，不是整个App或磁盘容量上限，也不承诺整个窗口配图全部取得。

预取直接复用共享 ReaderImages 的Cookie/跳转会话、Referer、namespace与重试失效规则，只落派生磁盘缓存，不新增预取内存图片副本。ReaderImages 新增可取消取得重载，Repository 将 Ticket 传至实际连接及流读取；取得和写盘均检查取消、窗口、时限及正文登录/namespace是否仍匹配。切窗口、打开阅读、离开发现页、后台、清理、修复模型和真正启动语义计算时暂停，正文始终优先。

沿用 RecommendationPolicy 的低电量、灭屏、省电、温度和内存限制；每次请求前复查网络。恢复系统条件不会主动唤醒，等待下次有效前台窗口调度。正常失败保留五分钟节流；被取消的在途条目撤回失败节流，避免回到原窗口后五分钟不能补图。有限时间片结束，不建后台服务、轮询或唤醒锁。原有磁盘空间检查和128MiB/1000项图片LRU淘汰继续有效。
