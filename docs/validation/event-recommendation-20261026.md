# 普通推荐中的事件复核、缓存与取消（2026-10-26）

当前状态：事件复核与装配现已接入普通DUAL LocalRecommendation；DiscoveryController不再因兴趣样本为空而跳过去重。未给手机安装、未发版；下列测试不等于全部语义去重或整App验收通过。

## 实现

向量齐备后，从最多384个当前成员规划至多24对，使用同一个RankingClient和模型进程做双向标题精排，再按联合策略装配共同事件池，随后执行个人兴趣排序。已有精确分组成员也在该有界窗口复用/补齐缓存向量。两个模型仍按原机制逐个加载。

复核共用原有15秒窗口。有内容兴趣样本时新增任务在最多3秒派发窗口内安排并预留约7秒给个人精排；无内容样本时已改为最多8秒派发、预留约1秒收尾（见 event-window-replay-20261026.md），不为不存在的个人精排保留7秒；单次native加载/运行可能跨越派发窗口，仍受原总窗口、读取优先级和关闭进程机制约束。这不是另加15秒后台任务或硬性3秒全部完成保证。最多48个新方向，但实际预算可能更早停止；剩余工作保留到后续整理，事件未全部完成时不声称fullyComputed，也不产出完整推荐对比。

单方向原始分数使用独立EventRerankCacheKey，绑定精确查询/目标标题及模型修订，不绑定抓取时间、平台偏好或当前事实策略；字段方向随实际标题输入，不能因成员ID顺序变化互换。缓存使用现有有界reranks表，不增加服务端或模型。每次装配仍核对端点元数据/时间、策略及当前反馈，不持久化永久等价结论。

打开阅读/离开/关闭沿原有client取消机制退出模型进程；配对扫描额外接收closed/finishing标记，及时停止共享存储线程上的扫描，不中断整个数据库执行器。关闭后的回传不发布列表。

## 比较池和学习来源

事件装配发生在三种技术排序之前，三者使用完全相同的事件池。ComparisonLearning.regroup仅在成员ID与文本哈希完全守恒时重新划分事件，保留原学习截止、ledger哈希、反馈哈希、版本、首次发现时间；丢失/新增/替换成员或别名不符均拒绝。相同池不重写既有学习记录。

前瞻策略指纹增加装配、事实和检索策略版本；旧准备记录在requireCurrent时失效，但不强行改写旧冻结记录。grouping_policy及父事件池哈希记录此次重组来源，不能把旧话题改名成新话题或重新采集一份较晚偏好来源来通过验证。
