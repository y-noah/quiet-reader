# 同一贴吧回复补齐迟到表情：源码与单元验证

## 已复现问题

首次来源快照的 emoji-img 只有不可用的 data 图片时，解析保留“表情”占位文字。后续同一明确楼层或楼内回复补齐 HTTPS 表情 URL，文字与回复 ID 不变，旧合并仅按已有 ID 跳过，媒体丢失；续读进展也只检查回复 ID。新增解析→合并→进展集合回归原代码 1 项失败，保留 before.log / before.xml。

## 实现边界

- 顶楼要求来源 post ID 与规范 section hash 一致；子回复保留来源 child ID，要求与 section hash 一致且有明确父楼。旧历史可缺 child ID，但只有新快照明确提供同一规范 ID 时才允许补图。无 ID 的相似文字或图片不据此猜身份。
- 只补同一回复、相同作者标签/回复对象/父楼/续读地址/源 ID、逐块完全相同文字与链接中的新增行内图片。已有图片不得丢失或替换；新增范围必须有序、非重叠、位于文本内，URL 必须 HTTPS。任何不一致保留原文。
- 纯函数复制改变的 section，保留旧时间证据，不修改已展示文档。合并后重建扁平 blocks，继续执行原条数和大小限制。续读进展增加明确身份回复的媒体 token，使没有新楼层的补图也能结束本次续读。
- child ID 为可选历史字段并计入大小；解码校验来源、嵌套/父关系及规范 hash。语义指纹仍由实际文字图片决定，冗余 raw ID 不改变指纹版本。没有新网络、轮询、缓存额度或模型工作。
