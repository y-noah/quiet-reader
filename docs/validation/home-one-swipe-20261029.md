# 有限首页：首屏加一次自然上滑

## 用户要求和实现

最新要求覆盖此前固定20条的临时设计：一批内容大约是首屏加一次自然上滑的量，滑到底不再追加，下拉或点击圆点才显式换批。没有要求凑满20条，也不靠压缩字体或截断标题凑数。

DiscoveryController 接受快照时，在来源过滤后的完整候选池中选择有限前缀。Activity 用一个不挂载的可复用 Card，按真实 ListView 宽度、系统字号、标题/简介/来源文字及实际卡片上下间距测量，预算为可用列表视口的1.6倍，最多测量20张（包含判断下一张是否超界）；20仅为安全上限。首张即使很长仍保留一条，供给不足不补重复项。首次尚未完成布局时用窗口尺寸和系统栏 inset 保守估计，常规路径使用实际 ListView 尺寸。

容量只在快照接受时计算，不在滑动、闲置或逐帧回调中重新计算。Controller、列表、曝光、试用及当前批次预读都使用同一批身份，完整排名池和持久快照不截断。屏幕/字号配置变化重建 Activity 后重新测量。没有新增联网、模型调用或后台定时器。

延续前轮绘制结束确认：成功接受列表后，真实 OnDraw 返回再结束显式刷新 busy；来源采集、模型整理和缓存仍可继续，但不延长已有列表的动画。失败/取消结束动画，重建取消旧 Activity 的未绘制监听。这是发布/绘制边界的补强；尚未在用户手机上确认是否解决“内容已换但还转”的反馈，不能宣称已确定其唯一根因。

## 失败和证据边界

初次沙箱构建不能访问已有ONNX Gradle缓存；保留 build.log，获得工具权限后同命令成功。签名工具首次未配置JAVA_HOME，保留 signature-env-failure.log，补正确工具环境后通过，没有改包或绕过签名验证。

普通升级基线首次误用针对schema6旧版的 normal-upgrade-before，当前已有schema9因此12项中1失败/code0；保留 normal-before.log。确认该阶段固定期待6后，使用已有 normal-upgrade-verify 核对schema9，升级前后均通过；没有清数据、重新造基线或放宽生产校验。

模拟手势不能等同用户真实手感；真实标题长度/字体/惯性和 Find X7 Ultra 的最终体验待下一轮手机授权。短时间截图和完成指示也不能证明用户全部刷新窗口都已修复。
