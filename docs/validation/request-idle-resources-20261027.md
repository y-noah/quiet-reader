# 请求空闲线程释放与当前代码回归（2026-10-27）

## 变更

RequestQueue此前使用不超时的固定工作池和单线程取消池。Repository仍存活时，即使请求已完成，线程仍常驻。改为同样最大3个请求线程、1个取消线程，空闲5秒自动退出，下次真实提交时再创建；使用ThreadPoolExecutor自身的空闲等待机制，不添加维护定时任务，不提高并发。新增单元测试验证取消后两池实际归零、队列未关闭及后续请求可重新执行；原有旧请求断开、迟绑定拒绝和关闭拒绝保持。

此项减少可释放线程栈的常驻时间；没有测量具体节省MB，也不能据此宣称耗电下降多少。
