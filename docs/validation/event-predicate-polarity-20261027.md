# 去重动作状态保护（2026-10-27）

## 缺陷与范围

恢复推荐主线审查后，发现 EventClaimEvidence v3 保护“尚未、并未”等全局标记，但“未能连任、未当选、未发布、能否发布、计划发布”仍可能与肯定标题一起准入模型任务。只判断两标题都含否定，也无法区分“未发布手机并开售平板”和“发布手机但未开售平板”。这是事实准入缺口，不是已经观测到用户真实新闻被误合并的证据。

先增加三项 JVM 回归；旧生产代码 13 项测试有 3 项失败，均为期望 CONFLICT 而实际 CANDIDATE。baseline.xml 和 baseline-retry.txt 保留；首次 baseline.txt 因共享 Gradle 缓存权限失败，没有运行新测试，不能当红色产品回归。

## 实现

EventClaimEvidence 升为 claim-evidence-v4-predicate-polarity，在每个候选 Prepared 中提取与具体已知动作关联的 negative、planned、questioned 状态。使用既有动作模式，不按人名、公司名或某条新闻增加特殊规则。紧邻限定词允许空白及最多两个明确连接词（成功、已经、能够、再次、继续、已、会、能），不跨越任意中间句子推断关系。

状态不同即拒绝事实准入；EventGroupAssembly 仍复查当前事实，所以旧任务或高分不能覆盖新规则。策略版本已进入既有 evidenceKey 和前瞻评估指纹，原始标题分数缓存身份保持。没有更换模型、增加编码、降低7.0双向门槛、叠加跨平台热度或修改代表来源。每候选特征仍有界，最多384候选、24任务不变。

保留“该公司发布手机，是否合理”的完成事实；“未能发布/没能发布”“计划发布/拟发布”可继续进入模型复核，不直接根据限定词认定等价。否定与计划的识别是浅层保守保护，不能证明所有复杂嵌套、转述、指代和否定范围均正确；未知表达仍可能漏判，不能据此称通用中文事件理解已完成。
