# 2026-10-29 有限整批缓存：真实三源与断网阅读

上一轮整批缓存的受控验证已完成，本轮新增真实网络证据，未更改生产实现或普通候选。目标是检验初始化/换批后的当前有限批次是否真正准备好，而非把候选列表或权限壳算成正文缓存。

## 方法

新增仅androidTest的 `LiveBatchCacheProbe` / `live-batch-cache` 入口，仅允许owned ranchu隔离Debug包。通过生产Repository.board实际获取IT之家12条、澎湃20条、BBC中文10条，排除item.video等后以39个真实候选初始化独立测试库。没有虚构标题/正文、注入加载器/传输、暂停模型或续期工作额度，也没有清空已有正文缓存。

实际DiscoveryActivity、Controller、有限列表容量、网络正文解析与原有模型调度照常运行；测试没有要求或证明这段短窗口中两个模型已经实际推理。当前列表正文必须同时满足可读、非权限/不可用/视频壳、候选版本匹配、RAM与实际磁盘文件正文指纹/获取时间一致。每250ms检查尚未准备好的条目，结果是被观察到的准备时间，含测试调度延迟。

首次准备结束后，通过正常Controller.refreshRecommendations调用与产品刷新相同的动作，再等待快照接受和实际列表绘制结束；没有用指针点击圆点，也不将本轮当指针手感验收。实际接受不同顺序和数量的有限批次，随后确认所有本批正文、旧批独有文件清理、至少两来源、HOME后被动viewport回调五秒没有新增正文文件或请求，以及反馈为空。

扩展轮最后结束首页、禁用该模拟器Wi-Fi和数据网络，确认Repository实际offline；逐源选择一篇当前缓存文章，清掉RAM并暂时排除该URL阅读历史，使用真实MainActivity原生阅读入口打开。没有传discovery_candidate，不把测试停留写成本人兴趣。对照获取时间、完整正文指纹、当前版本、没有DynamicReader/待获取任务，再核对真实WebView DOM含原文片段。全部正文来自上一步真实获取；没有离线回填。结束恢复原历史值与两项网络设置。
