# 真实文字热榜配图预取与离线阅读 / 2026-10-25

## 目标与方法

上一轮 ImagePreloader 仅有受控来源证据。本轮新增 live-image-prefetch 诊断：实时请求公开热榜，取前12个合法文字候选写入隔离测试数据库，打开真实发现页，由原生产控制器、正文预读器和配图预读器自动取得内容。不注入 Loader、URL连接或图片传输，不先打开文章，不手动请求正文/配图，不清理任何现有缓存来制造冷启动。

开始前记录图片文件名及内存键；只接受开始前两者均不存在且之后产生有效磁盘记录的图片。发现正文时检查元数据匹配。bodyInitiallyInMemory 仅表示起始RAM正文状态，不证明磁盘正文缺失或正文走了冷网络。因此下面的自动取得耗时不是冷启动/全篇下载性能，也不是手机性能。

确认新图片后，暂停发现投机工作，实际关闭模拟器 WiFi/移动数据，等 Repository.offline 为真，再用一个不能访问网络的新 ReaderImages 实例验证磁盘字节完全相同。通过真实卡片入口打开 MainActivity，验证没有来源WebView重载、版本匹配、正文可见，再滚动到该图片，检查实际解码、视口和溢出，取得可见帧截图。诊断finally和复用脚本均恢复原网络设置，不操作账号或验证码。

## 真实来源结果

以下均为 API36 项目模拟器；原始报告和截图位于 artifacts/local-ai/。

| 报告 | 样本及结果 |
|---|---|
| live-image-prefetch-thepaper-api36.txt | 公开热榜12候选、观察到12篇正文/23个选图URL；目标 newsDetail_forward_34324278，首次出现的图片95775字节；自动出现缓存6617ms，断网点击至正文可见1940ms；7项0失败，图片自然宽647，无溢出/无视频播放器 |

两篇均在点击前没有该图片的内存或磁盘副本；实际预取没有产生兴趣反馈。live-image-prefetch-thepaper.png、live-image-prefetch-ithome.png均已目视检查：正文与来源实际配图在统一页面可见。截图中的微博话题界面/手机登录画面是文章内图片，不是加载来源网页或登录界面。最终网络设置核对为原始1/1。

这里每个来源只证明一张新增图片的取得与离线复用。12篇正文/23或29个图片URL是观察范围，不能写成这些图片全部预取完成；发现一张合格新图片后即进入离线复用阶段。没有据此宣称整个窗口全图命中率、账号权限、真实用户喜好或所有来源完成。

新增脚本 scripts/test-live-image-prefetch.ps1 支持上述两源、报告与截图收集、项目AVD校验及外层网络恢复。相同榜单图片若已全部缓存，诊断可以失败说明缺少新增样本，不能通过清缓存或给旧图片盖新时间戳伪造取得证据。原始两轮直接运行诊断并手动取图，新增脚本尚未再次调用以免只重复相同样本；其语法检查另有报告。

## 从截图修复阅读细节

两张原截图显示已成功解码图片下仍永久提示“图片可能稍后显示”，alt也固定为“正文图片暂未显示”；提示与实际状态不符，图注链接只有小字号文字的点击高度。

ReaderHtml 改为中性“正文图片”alt及单一“查看大图”图注入口，去掉无状态依据的常驻提示；入口用至少44×44 CSS px点击区域和13px字号，补可访问名称说明失败可在大图中重试。仍由原大图控件提供实际错误与重试，不新增页面脚本/自动弹窗或重复操作。

最终构建 build-image-caption.txt：JVM385，失败/错误0，更新原有渲染用例，未添加只复述样式的新单元测试。实际点击链路新增测量现有图注目标及可访问名称：reader-image-portrait-15-caption-api36.txt、reader-image-landscape-15-caption-api36.txt均14/0，系统字号1.5下的图片/图注点击、图库前后/关闭、系统Back、后台释放与阅读位置保持通过。模拟器尺寸/密度/字号均由脚本finally还原。

最终 live-image-caption-ithome-api36.txt 为直接公开文章取得与实际统一阅读展示，readable1/1、probeErrors0、图片1440解码、无溢出；该轮不重新认证来源榜单，也不是新图片预取证明。live-image-caption-ithome.png已目视确认常驻提示消失、正文图可见、入口留有点击空间。44px与aria名称证据不等于完整TalkBack/无障碍验收。
