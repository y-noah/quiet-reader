# 刷新与重复首页修复验证（2026-10-31）

## 本轮结论及范围

刷新/重开稳定性范围通过；原签名、非debuggable、1.0.1/code50包 SHA256：0adafa4e33564b7959c82a0f03406a573ba78a4beca218c0fdb6ca8588bf5c9b。已保留数据原位安装到Find X7 Ultra；未发布GitHub。

本轮优先级为稳定好用，故不再使用“整轮15篇正文全部缓存好”作为手动刷新前置条件；预取仍继续，正文提前命中与页面切换分别衡量。本轮不声称所有正文、图片、评论已提前缓存，也不声称所有来源永远可访问。

## 两个实际原因

1. 原显式刷新被admission等待首15篇持久化锁住；单个慢来源可让整轮一直等待，取消/资源预算耗尽时保留旧屏，看起来像刷不出来。
2. 构造首页恢复active_snapshot；旧的展示冷却还依赖实际曝光及语义置信分段，未发完的候选可能仍反复落到顶部。此前不是每次都主动重新计算热搜池前N条，但实际恢复行为与用户期望不符。

## 修改与数据边界

- 有预备队列时用本地source/profile版本校验和快照换批；不等待Cookie扫描、全池正文/进度准备、模型或网络。无预备条目时保留既有进度证据刷新流程，并按整批发出记录轮换。
- 显式换屏直接发布原生列表，预取继续；动画通过原有preDraw同帧结束；快速点击合并，旧generation/epoch回调不能覆盖新请求。
- 新增独立presentations表（schema9→10），每批已发出的15条记录成员身份；最多2500项、7天。不同于实际曝光和阅读反馈，不增加兴趣或平台学习。
- 新建普通首页优先未发出的内容；同一首页从正文、后台或息屏恢复保留批次和位置。池耗尽按最早发出顺序有限回流，不能凭空生成新新闻。
- 来源、登录Cookie、账号命名空间、正文版本、禁用平台与偏好边界仍保留。未扩充来源、未调整相似去重。
