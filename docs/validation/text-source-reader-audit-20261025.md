## 现场发现：首次 Cookie 写入发生在 HTTP 错误路径

知乎首次读取时 `_xsrf` 发生变化，旧路径只在成功DOM取得后支持一次新会话重读；主框架 HTTP 403 会直接失败，随后会话检查把真实限制覆盖成“登录或缓存状态已变化”。现场报告不输出Cookie值。

`DynamicReader.retryChangedSession` 复用原有成功路径的重新读取规则，并接入主框架401/403错误：只有Cookie变化、缓存epoch/namespace仍有效、仍在原截止时间内、Activity仍有效、剩余次数为1时，释放旧来源页并重建一次。没有修改Cookie身份算法、忽略 `_xsrf`、把旧DOM改盖新会话、延长超时或增加循环。普通不变会话的权限限制不重试；取消仍能终止尚未开始的替代请求。

`CookieRotationProbe` 新增受控HTTP403回调场景：新会话正文、二次变化拒绝、取消，以及未变化的权限限制。使用合成host-only Cookie和截获HTML，经过真实WebView/解析器，但HTTP错误由生产回调的受控调用注入，不能当线上403已恢复成功。
