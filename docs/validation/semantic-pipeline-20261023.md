# 本地推荐管线阶段验证

日期：2026-10-23。目标真机：OPPO Find X7 Ultra / 12GB物理RAM / Android16 / ColorOS16。以下实际运行设备为项目 API36 x86_64 模拟器，不是该手机。

## 本轮实现

- SemanticOrder 保留多个独立正例和负例，最多各32条；重复文本不增加权重，最后一次极性有效。匹配阈值为待评估参数，不是概率。
- LocalRecommendation 将官方离线双模型接入向量缓存、同查询精排和冻结快照。每批最多48输入、2秒服务预算；单次窗口15秒，批间让出250毫秒。首次资源安装不在15秒窗口内，尚需单独完善安装体验。
- 不跨查询比较精排原始分数；仅在已评分的同查询组内融合名次，未评分位置保留。
- FeedStore v3增加有限大小的精排缓存。反馈/来源版本变更拒绝旧排序提交。
- Controller增加独立取消epoch，阻止排队中的准备任务在暂停、滚动、关闭、撤销或重置后启动；取消后的结果不能作为pending发布。
- 只有兴趣和候选均有向量才标记为语义排序。该标记不代表全部候选均已编码，状态显示向量完成数量。
- 屏幕关闭、省电、低电、温度升高和系统低内存时在批边界暂停。尚未补充即时温控监听和整应用PSS软阈值。

## 缓存升级、容错与清理

- 修正SQLite动态类型容错：文本或BLOB精排值不得通过getFloat隐式转换成0；非数值、非有限值、float溢出均淘汰为缓存未命中。向量要求BLOB类型、正确长度、有限且归一化。
- 向量/精排写入失败显式抛错，不把未成功落盘算成缓存成功。
- v1模拟旧库现在真正删除reranks表；新增v2无reranks表的实际SQLite升级，验证收藏、反馈与向量保留。
- 5000条精排缓存边界实测：读取刷新访问时间，新写入淘汰最久未使用项，容量保持5000。
- 新增偏好菜单“清理推荐缓存”：确认后取消采集/推理，清除候选、排序快照、向量和精排分数，刷新首页和来源状态。收藏、反馈、模型、登录不在清理范围内，不自动启动新一轮网络获取。
- `cache-upgrade-api36.txt`：62项通过；`cache-clear-ui-api36.txt`：21项通过。UI探针通过Controller调用清理并验证最终界面与存储；未把它描述为确认弹窗逐控件点击验证。
- 构建和197项JVM测试通过。旧版迁移/损坏/LRU小范围门槛已有证据，但300MB磁盘整体预算与真机内存/功耗仍未完成。

## 离线模型校验与恢复

- 本机推荐对话框新增“校验并修复模型”。独立IO executor运行，开始前取消推荐；修复期间不启动新推理；停止页面/销毁Controller会中断任务，版本标记拦截迟到UI更新。
- 快速installed检查现在同时核对每个文件存在且大小正确，不能只凭ready标记放过缺失文件。相同长度的损坏由引擎加载SHA-256和显式全文件修复发现；不在每次空闲调度时全量hash。
- 修复逐文件hash，只重拷贝损坏/缺失项。临时文件校验成功再替换，全部完成才提交ready。可用空间按当前待写文件加32MB检查，正常文件不重复复制。
- 新`model-repair` instrumentation模式用独立Context文件目录，从APK实际安装全部资源、改坏小文件首字节、校验恢复、删除文件重装、检查大文件修改时间未变以及提前中断。没有损坏正常安装目录，测试目录完成后清理。
- `model-repair-api36.txt`：7/0；`model-repair-semantic-api36.txt`：实际模型/缓存/温控回归9/0。构建与197项JVM通过。
- 当前证据不覆盖中途断电、真正磁盘耗尽、所有修复UI按钮和前后台时序；旧revision文件清理仍待做，真机ABI/内存/耗电验收仍未完成。
