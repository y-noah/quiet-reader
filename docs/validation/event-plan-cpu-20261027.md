# 事件复核规划减少重复计算（2026-10-27）

## 正式变更

EventVerificationPlan此前每对512维向量同时计算点积和双方平方模，384候选时每条向量会重复参与最多383次平方模计算；事实冲突/不足配对也先计算向量相似度。现在验证向量时一次保存平方模，使用最多384项double数组（3KiB），配对只算点积；现有Prepared事实准入先运行，不合格配对跳过向量与词面重叠计算。

未改变事实规则、相似阈值、24任务上限、排序、缓存键/版本、输入文本、模型、并发或定时调度。数学累加顺序保持，平方模重用，不先归一化float向量以免改动边界。新增永久测试保护极小/极大有限向量尺度下0.74/0.76两侧检索门槛。

## 对照证据

目录 `artifacts/local-ai/event-plan-cpu-20261027/` 保存改动前源码与原测试XML。只在本地artifact测试目录生成原规划器副本，用临时Gradle init脚本加入桌面测试源；不将基线副本或CPU诊断API放入App或永久测试源。首次诊断编译因Android编译bootclasspath没有java.lang.management失败，改为仅桌面JVM反射调用后通过，保留失败记录。

两组384候选与固定合成缓存向量，正/反输入次序，新旧24项任务的cacheKey、evidenceKey及每个double相似度的原始位均完全一致。相同线程CPU计时，预热3次、交替运行5次取中位：

|桌面合成窗口|改动前|改动后|
|---|---:|---:|
|同动作、配对均可准入|171.875ms|171.875ms|
|混合动作/冲突配对|78.125ms|46.875ms|

该系统线程CPU计时有约15.625ms量化，不能当微秒级性能证明；同动作场景没有可测收益。以上不能外推真实候选平均收益、ARM响应、耗电百分比或整App峰值。
