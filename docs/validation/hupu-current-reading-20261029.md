# 虎扑可见内容校验与隐藏节点修复

## 发现与修改

继续处理用户反馈的虎扑登录后仍受限问题时，先匿名读取当前热榜前三个帖子：643396204、643341520、643373728。三个帖子均有正文、回复与同帖下一页入口；这不是登录权限验证。

进一步核对发现 HupuDiscussion 的不对称处理：实际网页侧会剔除 hidden、aria-hidden 和显式隐藏样式的子树，内嵌内容侧则直接参与正文/图片签名比较。因此，即使同一份正文已在来源显示，只要含隐藏辅助节点，就可能被判为 loginRequired；回复也可能被过滤。对公开普通正文，还会把这些隐藏文字/图片带入统一阅读器。

新增四个测试，原生产代码的虎扑40项套件出现3失败：登录可见主帖误拒绝、可见回复丢失、公开正文导出隐藏内容；“完全隐藏的内嵌内容不能借另一段可见正文通过”仍成立。原始结果保留于 hidden-markup-baseline.xml/txt。

修复统一使用 visibleContent 处理内嵌内容签名、实际渲染签名和最终输出。结构化 JSON 的临时 DOM 原地清理，原网页仅在独立 clone 上清理，避免额外整页复制。回复视频判定保留在原始回复区域上，之后才清理输出，维持既有视频过滤行为。

账号存在、响应成功、允许的可见范围、线程/页码以及可见正文和有序图片的一致性要求仍保留；仅隐藏内容不构成可读正文。BODY_REVISION 从3升到4，联网时旧正文重新读取；离线允许旧缓存继续使用，不冒充已按新规则解析。
