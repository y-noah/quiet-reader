# 主动缓存的快速窗口往返与迟到回调

日期：2026-10-25。Android16/API36模拟器emulator-5560，隔离数据库与合成文字候选，生产DiscoveryController/ArticlePreloader/共享Repository缓存，受控正文传输。没有真实账号或平台访问。

## 新增边界

扩展既有PrefetchLifecycleProbe（mode=prefetch-lifecycle），保留旋转重建、真实HOME/返回、前台恢复不重复刷新来源等检查，并补充：

1. 首个窗口一篇正文完成并写入共享缓存，下一篇仍在获取时切到第20项窗口。
2. 立即返回原窗口，检查被取消的原请求能重新发起，不被真实失败的5分钟重试节流误伤；已完成正文从缓存复用，受控获取调用次数保持1。
3. 返回近窗口后交付被取消的远窗口结果，不能写缓存；对同一URL重新发起请求后再交付其旧请求结果，也不能以URL相同冒充新revision完成。
4. 新revision结果可正常缓存且元数据匹配；再次回到远窗口，其取消任务也可立即重试。
5. 页面重建之后交付重建前真正仍在进行的远窗口结果，不能污染替换页面；随后实际HOME取消、返回后恢复仍通过。

候选URL改为每轮时间戳身份，避免先前诊断写入的真实磁盘缓存让本轮误测暖缓存。不会清除个人缓存来制造冷启动。受控Loader只替换测试网络结果，其余调度、revision检查、缓存写入、取消和Activity生命周期仍走生产代码。
