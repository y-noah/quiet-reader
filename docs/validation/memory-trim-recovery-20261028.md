## 生产改动和边界

- RecommendationPolicy增加主App进程共享的30秒单调时钟恢复间隔，后续准入仍核对系统低内存、电量、温度等限制。间隔只是最低退让时间，不保证30秒后系统一定恢复。
- DiscoveryActivity收到真实内存等级通知时清除预读额度、到期/正文供应回调，取消修复、预读和推荐；原列表仍可读。MainActivity也记录同一恢复间隔，原有缓存释放和保留显式正文请求的trim行为保持。
- 小于RUNNING_LOW以及UI_HIDDEN不新建恢复间隔。仅进入后台不等于系统内存压力，后台原有取消行为继续执行。
- 没有恢复定时器、后台轮询、自动重新赋予缓存额度或新模型。间隔后，新的用户动作可恢复预读；所有系统限制仍须放行。推理进程本来已有独立trim退场逻辑，此处没有把Java静态字段当作跨进程共享状态。
- 编辑关注内容的普通暂停仍使用原suspendRecommendation，避免误加30秒内存限制。普通会话、偏好、热度、缓存格式/磁盘限额未修改。
