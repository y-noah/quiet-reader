# 先准备、后采集的新话题评价（2026-10-25）

本次完成可选的前瞻采样流程。它仍然输出观察记录，不自动认定独立留出，不是用户推荐收益验收。文字流热门内容的个人化推荐仍是产品主线；本功能只在用户主动进入本轮推荐评价时运行。

## 实现

新增“准备新话题评价”与“评价准备后的新话题”。准备时，FeedStore在同一事务固定截止时间、完整学习历史和当前有效画像指纹、偏好版本、模型清单revision、来源开关hash、排名策略版本和本次安装epoch。模型清单读取不加载原生推理或复制权重。记录当前数据库保留的全部候选ID/事件key/内容hash，以及已知历史学习身份。准备与评价选择均不写学习反馈。

刷新后，候选沿用原文字/中文/视频排除、屏蔽和归组规则；逐组验证所有成员首次入库时间严格晚于准备截止。已有ID、归组key、相同内容hash、本协议用过的事件或成员全部排除。未知first_seen、一个旧成员混入的新分组、已淘汰后同ID重新入库均不能突破已知身份排除。每轮最多100候选，三种顺序共享相同候选池并继续盲化展示前排并集。

正常刷新会改变来源数据版本，允许提供新候选。偏好变化/撤销/过期/阅读学习、来源开关变化、模型revision/排名规则/安装epoch变化则拒绝使用旧准备，提示重新准备。实际执行切换到备用模型也不能把不同模型的结果混入本组。规则过期的准备记录仍可读取，不能让旧策略记录阻止打开菜单、重新准备或清除。

对比完成后，在保存会话的同一个评价库事务中，将整个候选池（不只是已作选择的前排）加入本协议已用身份与内容hash。先消费候选，再接受选择；中途退出不能重抽同一批结果。协议状态独立于最近30轮记录的淘汰，旧会话淘汰不能使已用候选重新获得资格。旧准备的并发结果或重复保存拒绝且事务回滚。显式清除评价记录同时清除准备状态；重新准备建立新协议但保留已有评价会话。

评价数据库从schema1升级到2，仅新增单行evaluation_protocol表，保留原sessions和labels。FeedStore仍schema6，默认App版本未改。观察导出器支持评价库1/2，允许列表保存协议截止、hash、已知/已用身份，拒绝旧成员、旧时间、模型或学习指纹变化。协议字段没有标题、正文、URL、Cookie或原始学习文本。所有层级仍holdout_qualified=false；严格独立评估器继续拒绝观察信封。
