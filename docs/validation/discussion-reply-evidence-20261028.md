# 讨论回复的来源时间证据

本轮补 V2EX 的稳定回复身份与来源绝对创建时间，尚未启用讨论进展绕过冷却。没有修改名称、图标、手机安装包或发布版本。

## 依据与实现

通过公开 HTTPS 请求核实 `https://www.v2ex.com/t/1251768`：`r_18219649` 对应 `.ago[title="2026-10-26 09:37:39 +08:00"]`。测试资源只保存前三条回复编号、title 和相对时间显示文案，不含账号、正文或 Cookie。测试正文为合成内容；该元数据样本不证明真实完整分页或登录权限。

- 保留已有 `v2ex-r_编号` 身份；只有合法数字编号、唯一 DOM 身份、唯一正文区域和所属 cell 的唯一时间字段才采集证据。fallback 内容 hash 身份不能用于该证据。
- 严格解析包含明确时区的绝对日期，拒绝不存在的日期、未来时间、无时区和相对时间。正文引用、嵌套卡片、页头时间均不能赋给回复。
- 对每个文档一次建立最多 2048 个回复身份的临时索引，不为每条回复重新扫描整个文档；超量放弃时间证据。无额外联网、模型、定时器、后台服务或数据库表。
- Section 增加版本化回复时间，ReadingHistory 保存/恢复；旧缓存缺失时保持未知。解码复核来源帖子 URL、稳定回复编号、时间数值类型、版本、范围和楼层类型。
- ArticleDiskCache 入队时复制元数据，避免调用方后续修改污染异步写入。DocumentSize 同时计入堆对象及序列化开销。

## 后续接线

必须先建立同账号 scope、同来源帖子、同真实曝光/阅读基线下的有界回复快照，区分新增回复与分页补齐的旧回复。创建时间晚于整个事件最近真实展示只是必要条件；还需明确更新段落及实质新增信息，才能考虑同兴趣质量层内重新入选。新增编号、回复数、旧回复编辑或排名变化不能直接重推。贴吧、虎扑时间证据要分别从实际结构核实，不能套用 V2EX。

当前新闻 ArticleProgressEvidence 仍明确排除 V2EX；这些字段没有单独触发推荐、兴趣学习或刷新。整体真实账号/完整分页、推荐收益、ARM 整 App 峰值、拔线耗电温升和长期缓存验收仍开放。
