## 发现并修复当前准入缺口

原谓词限定只识别“是否道歉/未道歉/计划道歉”等相邻形式，遗漏“是否/未/计划 + 就某事 + 道歉”，且未区分明确“去年”和“前年”。新通用合成测试对旧代码复现 3 项中 2 失败：是否就某事道歉仍为 CANDIDATE，去年/前年被当同类断言。首轮正例测试误要求提问包装后的精确同文必须 CANDIDATE，实际已 ALREADY_GROUPED；保留该测试错误日志，修正为接受原有精确归组后再取得上述 2 个旧代码失败，未据此修改生产以迎合测试。

EventClaimEvidence v15-qualified-apology：只对道歉谓词允许限定词与动作间存在“就/为/因/针对 + 原因”短语，最长 32 字且不跨逗号/句号等句界；明确去年/前年保留各自标记，不泛化所有时间，也不把后面“球迷是否接受”倒算成否定原道歉。原有其他动作限定方式不改。对当前与受限定的道歉断言，准入、任务检索和最终装配重新检查；即使注入旧任务 99/99 分数，也保留双入口。

修复后专项 3/0，覆盖 13 类限定、四种原因连接、不同年份、正常完成与独立后问，原高分任务也不能绕过；完整 JVM 867/121 套，失败/错误/跳过 0，lintDebug/lintRelease 通过。证据 artifacts/local-ai/question-frame-ablation-20261029（冻结脚本/输入、模型分数与摘要、修复前后 XML/日志、完整回归）。
