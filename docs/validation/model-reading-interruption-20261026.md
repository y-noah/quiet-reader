# 真实模型计算切换阅读（2026-10-26）

## 目的与方法

安静缓存入口较快不足以解释此前带模型回放的首篇长等待。本轮新增ModelReadingInterruptionProbe，使用实际DiscoveryController、FeedStore、LocalRecommendation、RankingClient和独立RankingService，100条合成中文候选、一个显式兴趣和已经缓存的目标正文。安装/文件校验在测量窗口前完成，不是首次安装测试。

通过测试侧监听实际模型ITEM回报，在初筛512维向量或精排有限logit确实产生后，同一主线程回调立即调用首页正常open入口。先调用原生产监听，再进行打开，不伪造模型结果、不替换模型或取消实现。固定回调时序用于隔离诊断，不是手指点击、真实推荐收益或物理帧性能。

普通入口保留controller.handoff/stop、元数据、会话与缓存校验。当前生产代码没有改动：open已经在startActivity前停止推荐；不为没有复现的原因引入性能补丁。

## 结论边界

当前受控条件支持“阅读动作能中断两个真实模型阶段，模型进程及时释放”。它不能解释先前R8完整回放约9.9秒首篇，也不能证明所有加载中断、来源网页/刷新/预读竞争、手机功耗温度或峰值内存通过。精排阶段Binder死亡210ms而DOM1063ms，至少本次后段等待不是存活模型进程持续推理；仍可能有绘制、调度和测试负载差异。不能据此宣称首篇性能已修复，也不能按不同负载/包类型的数据计算提速收益。

下一步保留同一计时定义，核对当前混淆包和实际来源活动；真机观察仍等用户方便连接，不操作已拔线手机。
