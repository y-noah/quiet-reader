# V2EX 讨论进展接线及边界

本轮将带来源时间的新回复接入现有显式推荐换批；仅本地 Debug/Android 16 隔离验证。普通候选及手机包未更新，没有推送或发布。R8/普通候选和整体目标尚未验收完成。

## 实现

- DiscussionProgressEvidence 保存主帖/补充与回复的文字分片 hash、hash 后的稳定回复编号及来源创建时间。主线程只冻结至多 128 节、512 block、24000 字符的不可变字符串/标量；worker 计算并最多保留 4000 个正文 hash 项。超过边界放弃本次证据，不截断后宣称完整。
- 新闻和讨论使用不同的 JSON version 及明确子类型；讨论子结构缺失/版本错误不能退化为新闻证明。讨论状态包含完整 union 校验、有界编号数/时间类型、正文和标记集合关系，主帖至少 32 个 hash、总正文至少 100 个 hash / 240 个汉字。只保留 ASCII hash，不保存原回复、作者或 Cookie。
- 沿用 schema9 的 article_progress、有界 256 行 / 7 天 / 8MiB 逻辑载荷、事务、scope 和真实曝光/有效阅读基线。没有新增表、后台定时器、来源请求或模型推理。未知时间可以作为已获取正文基线保留，但不能标记新进展；主帖尚无回复时不制造来源时间。
- 同一精确候选身份和账号 scope、晚于最近实际展示/阅读的新获取版本，且主帖保留至少 80% 原正文 hash，才继续检查新回复。新回复必须使用从未在该基线出现过的稳定 ID，来源创建时间晚于基线获取与整个事件最后展示；新回复自身至少 96 个新 hash、至少 64 个来自明确更新段落的新 hash，才产生候选进展时间。沿用既有新闻更新标签识别，不声称结构阈值等同真人语义价值判断。
- 旧分页、已知 ID 的编辑、改标题/涨热度、相对时间、不同 ID 重贴旧正文或微小插字不能绕过冷却。缺少明确更新段落/可靠时间时保守保留冷却。不同 URL 的讨论不走新闻跨 URL 后续捷径。
- ArticleProgressBinding/Preparation 与当前 worker 预筛、账号校验、有效阅读、显式刷新接线。先采集不改曝光、兴趣/平台偏好和正在阅读的列表；只有显式换批才可能重新展示。实际再次展示/有效已读会消费证明；账号、namespace、生命周期/任务取消仍拒绝迟到结果。
